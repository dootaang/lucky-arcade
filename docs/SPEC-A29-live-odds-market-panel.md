## 0. 한 줄

**암호화폐 거래소의 호가창처럼, 카지노 어느 테이블이 지금 뜨거운지가 실시간으로 요동친다.**

## 1. 정체가 바뀌었다 — 확률 패널이 아니라 시장 패널이다

백로그에 기록할 때 이 아이디어는 **인물별 조커 보유 확률**을 띄우는 것이었고, 착수 전 미결 질문이 셋이었다.

```
Q1  현재 보유 확률인가 최종 보유 확률인가
Q2  관전은 손패가 공개돼 확률이 0/1로 붙는다. 그럼 무엇이 요동치는가
Q3  직접 플레이에서 publicRead 범위를 넘지 않아야 한다
```

**A26이 Q2에 답을 주면서 셋이 한꺼번에 풀렸다.** 흔들려야 하는 것은 조커 확률이 아니라 **시장**이다.
NPC 35명이 24시간 테이블을 돌아다니며 판돈을 걸고 있으므로, **어느 테이블에 얼마가 몰려 있는가**가
그 자체로 계속 변한다. 확률을 계산하지 않으므로 Q1과 Q3은 질문 자체가 사라진다.

- 손패를 보지 않는다 → 정보 누출이 구조적으로 불가능하다
- 확률 모델이 없다 → 정의 논쟁이 없다
- A26의 `npcDaySessions`가 이미 `tableId`·`stake`·`minuteOfDay`를 들고 있다 → **추가 계산 0**

## 3. 값의 정의 — 여기가 이 명세의 핵심

### 3.1 왜 단순 합이 아닌가

"최근 30분간 판돈 합"으로 하면 **값이 계단식으로 튄다.** NPC 세션은 몇 분에 하나씩 일어나므로
30분 창에서는 30분에 몇 번만 바뀐다. 그건 요동이 아니라 정지 상태에 가깝다.

### 3.2 지수 감쇠 가중 합

각 세션의 기여가 시간이 지날수록 줄어든다.

```
heat(table, now) = Σ  stake_i · 2^( −(now − minute_i) / HALF_LIFE )
                   i ∈ 그 테이블의 세션 중 minute_i ≤ now

HALF_LIFE = 12분
```

- 매 틱마다 모든 항의 가중치가 조금씩 줄어들어 **값이 연속적으로 움직인다.**
- 새 세션이 들어오면 확 뛴다. 그게 벽이 쌓이는 순간이다.
- **보간이나 가짜 노이즈를 넣지 않는다.** 이 값은 실제로 매 순간 다른 진짜 수치다.
  표시 숫자를 흔들기 위해 없는 값을 만들지 마라.

### 3.3 순수 함수다

```ts
export function tableHeat(sessions: readonly NpcSession[], utcMinute: number, halfLifeMinutes: number): number;
export function marketSnapshot(profiles, clock, contract): {
  tables: readonly { tableId: string; heat: number; seated: number; delta: number }[];
  movers: readonly { npcId: string; delta: number }[];
};
```

A26과 같은 규율이다. `Date.now()`를 부르지 않고 시계를 주입받는다. 유닛 테스트가 시각을 고정한다.

## 4. 움직임 — 현혹은 여기서 나온다

관찰한 바로, 호가창이 눈을 끄는 것은 색이 화려해서가 아니라 **짧은 보간 + 잦은 갱신** 때문이다.
부드럽게 만들려고 길게 늘이면 그 순간 우아해지고 심심해진다.

```
갱신 주기        500ms
막대 transition  160ms  cubic-bezier(.34, 1.2, .64, 1)   ← 1.2 오버슛이 탄력을 만든다
플래시           420ms  ease-out
행 자리바꿈      220ms
```

### 4.1 막대는 `width`가 아니라 `transform: scaleX`

```css
.odds-fill { transform-origin: left; transform: scaleX(var(--heat)); transition: transform 160ms cubic-bezier(.34,1.2,.64,1); }
```

`width`를 트랜지션하면 매 프레임 레이아웃이 다시 계산된다. 9행은 버텨도 나중에 행이 늘면 무너진다.
`scaleX`는 합성만 하므로 GPU에서 끝난다. **`.ca-*` 예산 규칙(transform·opacity만)과 같은 이유다.**

### 4.2 플래시는 애니메이션을 재시작해야 한다

같은 방향으로 연속 변할 때 다시 번쩍이게 하려면 리플로우를 강제해야 한다.

```ts
row.removeAttribute("data-flash");
void row.offsetWidth;              // 이 줄이 없으면 두 번째 변화부터 안 번쩍인다
row.setAttribute("data-flash", direction);
```

호가창 구현에서 가장 흔한 실수다. 빼먹으면 첫 변화만 보인다.

### 4.3 숫자는 등폭이어야 한다

```css
font-variant-numeric: tabular-nums;
```

숫자 폭이 다르면 값이 바뀔 때마다 글자가 좌우로 흔들린다. 그건 요동이 아니라 지저분한 것이다.
호가창이 전부 등폭인 이유다. `.ca-num`이 이미 이걸 한다.

## 6. 자리

**카지노 플로어**다. 테이블 목록 위나 아래에 둔다.

이유는 장식이 아니다. **어느 테이블이 뜨거운지 알면 거기로 가게 된다.** 실제 게임플레이 유인이 되고,

## 7. 절대 어기지 않을 것

1. **게임 판정에 영향을 주지 않는다.** 이 패널을 통째로 지워도 동일 시드 `resultHash`가 같아야 한다.
2. **손패를 읽지 않는다.** 입력은 A26 세션 데이터뿐이다. 진행 중인 대국의 상태를 참조하지 마라.
3. **표시 숫자를 흔들기 위해 없는 값을 만들지 마라.** 감쇠 합은 진짜 수치다. 노이즈를 더하는 순간
   유저에게 거짓말이 된다.
4. **순수 계층에서 `Date.now()`·`Math.random()`을 부르지 마라.**
5. **유저 지갑과 닿지 않는다.** A26의 A안이 그대로 유효하다.
6. `prefers-reduced-motion`에서는 막대 트랜지션·플래시·자리바꿈을 전부 끄고 값만 바꾼다.
7. **갱신 타이머는 탭이 백그라운드일 때 멈춘다.** `visibilitychange`. 보이지도 않는 패널이
   500ms마다 도는 것은 배터리 낭비다.

## 9. 접근성

- 패널 전체에 `aria-live`를 걸지 마라. 500ms마다 갱신되는 영역이 스크린리더를 점거한다.
- 표는 `<table>`로 마크업하고 테이블명·인원·금액을 헤더로 준다.
- 등락은 색만으로 전달하지 말고 `↑ ↓ —` 기호를 같이 둔다. 색각 이상에서 색만으로는 안 읽힌다.
- 감쇠 합은 근사치이므로 화면에 `추정`이라고 쓰지 말고, 단위만 `P`로 두고 정확한 수치인 척하지도 마라.
  **표시값은 실제 계산 결과 그대로다.**

## 10. 테스트 관문

1. `tableHeat`가 같은 입력에 같은 값을 낸다.
2. 세션이 하나도 없는 테이블의 열기가 정확히 0이다.
3. 감쇠 반감기가 12분일 때, 12분 전 세션의 기여가 정확히 절반이다.
4. 시계를 앞으로 밀면 모든 열기가 단조 감소한다(새 세션이 없는 구간에서).
5. 순수 계층이 `Date.now()`·`Math.random()`을 부르지 않는다.
6. 패널을 비활성화해도 동일 시드 `resultHash`가 같다.
7. 막대가 `width`가 아니라 `transform`으로 움직인다(계산 스타일 검사).
8. 같은 방향 연속 변화에서 플래시가 매번 재시작된다.
9. `prefers-reduced-motion`에서 트랜지션·애니메이션이 0이다.
10. 탭이 숨겨지면 갱신 타이머가 멈춘다.
11. 초기 JS gzip 예산을 넘지 않는다.

## 11. 하지 않는 것

- **조커 확률을 계산하지 않는다.** 그건 다른 기능이고, 하려면 `publicRead` 경계부터 다시 논해야 한다.
- **유저 간 실시간 동기화를 하지 않는다.** 모든 값이 클라이언트에서 계산되며 서버가 없다.
- **베팅 UI를 여기에 붙이지 않는다.** 이 패널은 읽는 것이다. 거는 것은 각 테이블 안에서 한다.
