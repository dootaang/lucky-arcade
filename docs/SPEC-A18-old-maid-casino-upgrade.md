# SPEC-A18 — 테메로세 도둑잡기 카지노 고도화

> 상태: 구현 완료 (2026-07-25).
>
> 이 문서는 도둑잡기 고도화 작업의 단일 정본이다. 병렬 작업자는 구현 전에 문서 전체를 읽고,
> 아래 파일 소유권과 데이터 계약을 바꾸지 않는다. 계약 변경이 필요하면 구현하지 말고 원 Codex에 보고한다.

## 1. 목표와 범위

이번 단계에서는 새 카지노 게임을 만들지 않는다. 공개된 테메로세 도둑잡기를 먼저 다음 수준으로 올린다.

1. 4인 NPC 관전 모드에 결과 예측 포인트 베팅을 붙인다.
2. NPC 선택 풀을 정본 주요 인물 약 30명으로 넓힌다.
3. NPC 네모는 `nemo-magical-girl` 외형으로 고정한다.
4. 바치칼(`bacikal`)은 신규 NPC 선택 풀에서 제외한다.
5. 매 판에 사용하는 짝 카드 수와 세로형 인물 카드 풀을 확대한다.
6. 1,592개 후보를 전부 배포하지 않고, 승인된 세로형 인물 파생본만 단계적으로 컴파일한다.

## 2. 호환성과 버전 계약

- 현재 규칙 버전은 `old-maid/0.6`, 테메로세 팩은 `temerosa-old-maid/0.6`이다.
- 상태 구조가 바뀌지 않으면 규칙 버전은 유지한다.
- 카트리지 데이터가 바뀌므로 테메로세 팩은 `temerosa-old-maid/0.7`로 올린다.
- 기존 저장 복구를 위해 기존 캐릭터 ID와 기존 얼굴 ID를 삭제하거나 다른 의미로 재사용하지 않는다.
- 바치칼 데이터는 레거시 복구용으로 남길 수 있지만 신규 상대 후보에는 절대 들어가지 않는다.
- 기존 네모 ID `nemo`는 유지하며, 그 ID가 가리키는 NPC 외형은 마법소녀 네모 하나뿐이다.

## 3. 카트리지와 코어 계약

`OldMaidCartridge`에 다음 선언형 필드를 둔다.

```ts
interface OldMaidCartridge {
  // 기존 필드 생략
  readonly selectableCharacterIds: readonly string[];
  readonly dealPairCount?: number;
}
```

- `selectableCharacterIds`는 신규 대국에서 무작위/수동 선택할 수 있는 NPC의 명시적 허용 목록이다.
- 목록의 모든 ID는 `characters`에 존재해야 하고 중복되면 안 된다.
- 테메로세 팩의 목표는 약 30명이다. 정확히 30명을 맞추기 위해 정본 근거가 약한 인물을 넣지 않는다.
- `dealPairCount` 미지정 시 기존값 12를 사용한다. 기존/개인 카드 카트리지의 동작은 바뀌지 않는다.
- 테메로세 팩은 승인된 얼굴 재고를 확인한 뒤 18을 기본 목표로 한다. 카드가 부족하면 조용히 축소하지 말고 데이터 검증에서 실패시킨다.
- 실제 대국은 전체 카트리지 카드에서 시드로 `dealPairCount`개의 서로 다른 짝을 고른 뒤 조커 1장을 더한다.
- 결과 판정과 CPU 뽑기에는 이미지, 대사, 베팅 잔액을 전달하지 않는다.

## 4. 에셋 계약

- 원본 CharX/RisuAI 카드와 원본 추출물은 저장소와 웹 배포물에 넣지 않는다.
- 후보는 실제 바이트 MIME, 안전성, 인물 정규화, 세로형 구도, 정본 주요도 순으로 검사한다.
- 1차 배포 목표는 **승인된 세로형 인물 카드 얼굴 최소 160장**이다.
- 30인 NPC 좌석용으로는 인물마다 최소 `neutral`, `pleased`, `tense`, `despair` 역할을 검수한다.
- 카드 얼굴은 좌석 감정 4종을 모두 갖추지 않아도 되며, 매핑되지 않은 감정을 발명하지 않는다.
- 파생본은 `sm`과 `md`를 만든다. 일반 손패/뒷면은 `sm`, 상세 보기와 큰 초상은 필요할 때만 `md`를 요청한다.
- 같은 원본 바이트와 같은 시각 결과는 콘텐츠 주소로 중복 제거한다.
- 승인 상태는 `candidate | approved | rejected`로 기록하며 `approved`만 런타임 매니페스트에 들어간다.

## 5. 관전 베팅 계약

### 5.1 대상과 시점

- 베팅 대상은 **최종 조커 보유자**다.
- 4인 NPC 관전 대국을 시작하기 전에 NPC 한 명과 판돈을 선택한다.
- 판돈은 `10 P`, `50 P`, `200 P`다.
- 시작 트랜잭션에서 판돈을 예약하지 못하면 대국을 시작하지 않는다.
- 대국 도중 대상과 판돈을 바꿀 수 없다.

### 5.2 정산

- 적중: 예약 판돈 반환 + 순이익 `3 × 판돈`.
- 실패: 예약 판돈 소멸.
- 중단/복구 불가: 확정 결과가 없으면 예약을 반환한다.
- 관전 대국에는 순위 보상을 지급하지 않는다.
- 사람이 직접 참가해 정상 완료하면 1·2·3·4등에 각각 `60·30·15·5 P`를 지급한다. 선택 베팅 여부와 무관하다.
- 신규 사용자의 포인트는 `0 P`다. 기존 메달 잔액은 A13 계약대로 1:1 포인트로 보존한다.

### 5.3 멱등성과 재시도

- `outcomeKey`는 최소 `cabinetId + packVersion + seed + mode + participantIds`를 정규화해 만든다.
- 동일 `outcomeKey`에는 유료 베팅 정산을 한 번만 허용한다.
- 같은 시드 다시 보기는 무료 리플레이만 허용하며 추가 수익/손실이 없다.
- 예약, 정산 영수증, 지갑 변경은 한 IndexedDB 트랜잭션에서 커밋한다.
- 새로고침, 완료 화면 재진입, 복구 재생으로 중복 지급 또는 중복 차감이 일어나면 실패다.

## 6. UI와 로딩 계약

- 준비 화면에서 `직접 참가`와 `NPC 관전·예측`의 차이를 분명히 보인다.
- 베팅 패널에는 현재 잔액, 대상, 판돈, 가능한 순손익을 시작 전에 표시한다.
- 포인트가 부족해도 직접 참가 무료 테이블은 항상 시작할 수 있다.
- 관전 중 모든 손패 공개 규칙은 유지한다.
- 완료 화면의 버림패가 프레임/텍스트 위로 새어 나오지 않도록 기존 클리핑과 레이어 규칙을 회귀시킨다.
- 160장 이상의 `md` 이미지를 일괄 선로드하지 않는다. 현재 좌석, 현재 손패, 상세 보기 중심으로 요청한다.
- 에셋 로딩 실패는 규칙 진행을 막지 않으며 텍스트/카드 뒷면 폴백을 제공한다.

## 9. 완료 관문

- 신규 NPC 후보에 `bacikal`이 없고 `nemo`는 마법소녀 외형 하나만 사용한다.
- 선택 가능한 모든 NPC가 필요한 좌석 초상과 이름을 갖는다.
- 테메로세 대국은 확대된 카드 풀과 `dealPairCount`를 쓰며 같은 시드/입력의 `resultHash`가 재현된다.
- 기존 개인 카드 카트리지는 12쌍 기본값으로 회귀 없이 동작한다.
- 관전 베팅의 적중, 실패, 잔액 부족, 중단 반환, 복구, 중복 정산 방지가 테스트된다.
- 무료 직접 참가 보상과 유료 관전 정산이 섞이지 않는다.
- 초기 JS 예산 200 KiB와 콘텐츠 감사 관문을 통과한다.
- 데스크톱과 모바일에서 준비, 관전, 완료 화면을 브라우저로 확인한다.

## 10. 구현 결과

- 감사 후보 1,516종 중 205종을 육안 승인했고, 세로 카드 얼굴 189종을 확보했다.
- 런타임 201종을 `sm/md` WebP 402개로 컴파일했다. 총 배포 크기는 14,805,646바이트다.
- 기존 핵심 인물과 감사된 30인 명단을 합쳐 바치칼을 제외한 약 34명을 선택 가능하게 했다.
- 네모는 기존 `nemo` ID와 마법소녀 외형만 사용한다.
- 기존 카드 얼굴과 신규 승인 에셋을 합친 전체 풀에서 판마다 18쌍과 조커, 총 37장을 결정론적으로 고른다.
- 관전 베팅은 10/50/200 P 예약, 적중 순이익 3배, 실패 시 판돈 소멸, 동일 결과 재정산 금지를 적용했다.
- 직접 플레이는 완료 순위에 따라 1등 60 P · 2등 30 P · 3등 15 P · 4등 5 P를 지급하고 관전에는 무료 보상을 지급하지 않는다.
- 첫 화면과 손패는 `sm`, 카드 상세만 `md`를 사용하며 전체 이미지 파일을 선로드하지 않는다.
- `pnpm check`, 콘텐츠 감사, 전체 Playwright 19개 통과(6개 조건부 스킵)를 확인했다.
