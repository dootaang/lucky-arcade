# A37 카지노 흐름 경제

## 목적

기존의 목표 잔고 평균회귀형 NPC 시뮬레이션을 실제 유입·대국·지출이 이어지는 결정론적 흐름 경제로 교체한다. NPC의 승패를 잔고에 맞춰 조작하지 않으며, 모든 정산 행은 실제 라운드나 실제 자금 이동에서만 생성한다.

```text
외부 생계 → NPC 외부 준비금 → NPC 카지노 지갑
                                  ↕
                         NPC · 플레이어 · 하우스
                                  ↓
                         활동 기반 하우스 운영비
```

## 불변 조건

- 카지노의 날짜·정산 경계·시뮬레이션 기준은 모두 `Asia/Seoul`이다. 저장 시각은 모호하지 않은 Unix UTC 초를 계속 사용한다.
- 워어즈는 하우스 역할이며 일반 도박 NPC, 명예의 전당, NPC 손익 순위에서 제외한다.
- NPC끼리의 게임은 제로섬이고, 하우스 게임의 NPC 손익은 하우스 손익의 반대 부호다.
- 플레이어의 실제 게임 거래는 로컬 브라우저 원장에 반영되고, NPC 및 하우스 잔고에도 같은 로컬 가지로 반영된다.
- NPC에게 무자본 보상을 발행하지 않는다. 무자본 도둑잡기 보상은 플레이어 전용이다.
- 외부 생계 수입은 외부 준비금으로 들어온 뒤 일부만 카지노 지갑으로 이동한다. 카지노 투입만 내부 포인트 공급을 늘린다.
- 하우스에 정기 외부 수입을 발행하지 않는다. 운영비는 실제 테이블·라운드·양의 게임 매출에 비례해 소각한다.
- 개인 잔고 상한과 결과 조작은 두지 않는다. 지급 능력은 판돈 노출 한도로 통제한다.

## 계약과 결정성

`npc-ledger/1.2`와 `casino-flow/1.0`은 아직 출시되지 않은 후보 계약이다. 기본 release flag는 꺼져 있으며 날짜가 지나도 런타임은 `npc-ledger/1.1`을 유지한다. `(npcId, KST day, field)`를 씨앗으로 삼아 다음 일일 변동만 결정하므로 서버 없이도 모든 브라우저에서 같은 공통 NPC 세계선을 재현한다.

- 개인별 정산 시각
- 당일 외부 총수입
- 당일 카지노 예산 비율과 투입액
- 방문 횟수, 방문당 라운드 수, 게임 선택, 판돈과 중단 행동

정산은 KST 하루에 정확히 한 번만 발생하고 거래 ID와 멱등 키도 날짜·NPC에 고정한다. 외부 준비금은 음수가 될 수 없다.

NPC의 성격·숙련도·선호 게임·생계 계약은 해시로 만들지 않는다. 기존 34명의 작성된 계약을 승계하거나 외부에서 명시적인 `TemerosaFlowAuthoredProfile`을 제공해야 한다. 누락된 신규 인물은 `missing-authored-profile` 사유로 경제 활동에서 제외한다.

## 행동과 활동 밀도

공용 의사결정 코어에 NPC별 행동 벡터를 입력한다. 현재 흐름 계약은 하루 3~7회 방문, 방문당 4~12라운드를 사용한다. 손절·익절·손실 추격·위험 선호·게임별 실력은 인물별 값이며, 잔고가 최저 판돈보다 작으면 유료 게임을 만들지 않는다.

라이브 플레이 테이프와 최근 정산은 같은 실제 세션에서 파생한다. `npc-income` 행은 게임 손익에서 제외하고 `본업 정산` 또는 `카지노 예산 투입`으로 구분한다.

## 하우스 운영비

하루 운영비는 다음 활동량으로 계산하고 23:50 KST에 한 번 정산한다.

```text
기본 시설비
+ 열린 테이블 시간 × 단가
+ 실제 라운드 묶음 × 단가
+ 양의 게임 총매출 × 비율
```

보호 준비금 아래로는 비용을 지출하지 않으며, 지불하지 못한 비용은 `curtailedAmount`로 감사한다. 흐름 계약의 현재 보정값은 라운드 100회당 20 P, 양의 게임 총매출의 30%다. 하우스에 별도 외부 수입을 두지 않아 NPC 예산 투입을 상쇄하는 유일한 자동 조절기는 실제 활동 비용이다.

## 출시 후보와 로컬 가지

- 2026-08-01 00:00 KST (`KST day 20666`)은 감사 재현용 후보 epoch일 뿐 자동 출시일이 아니다.
- 명시적인 `flowEconomy` release flag가 없으면 후보 날짜 이후에도 `npc-ledger/1.1` 결과를 그대로 사용한다.
- 실제 epoch은 전체 시리즈 명부·프로필·에셋·경제 감사를 마친 뒤 새로 지정한다.
- 실제 경계 시점의 NPC 잔고와 하우스 잔고를 `1.2` 개장 잔고로 이월한다.
- 각 브라우저의 경계 이전 플레이어 거래도 이전 계약으로 재생한 뒤 정확한 로컬 NPC·하우스 잔고를 이월한다.
- 경계 이전에 예약된 관전 베팅은 새 계약으로 다시 해석하지 않고 원래 마감 시각의 계약으로 정산한다.

현재 흐름 후보 계약은 경제 코어 검증을 위해 기존 34개 NPC ID만 사용하며, 생성된 116인 명부를 런타임에 연결하지 않는다.

## 전체 등장인물 편입 경계

출시 신원 정책은 `series-persona`로 고정한다. 같은 인물이어도 작품이 다르면 지갑·전적·랭킹·성격이 서로 다른 NPC다. `canonicalPersonKey`는 관계 표시 전용이다.

- 출시: `series-persona`
- 실험 도구에서만 허용: `canonical-person`

어느 정책에서도 워어즈/하우스 역할은 제외하고 기존 잔고는 후계 ID 하나에 정확히 한 번만 옮긴다. 출시 경로는 `canonical-person`을 선택할 수 없으며, 현재는 어댑터와 정책 테스트만 있고 전체 명부는 런타임 계약에 연결하지 않는다.

## 화면 표시

카지노 플로어는 다음 값을 공통 세계선과 로컬 거래를 합쳐 표시한다.

- 오늘 NPC 카지노 유입
- 오늘 하우스 게임 손익
- 오늘 하우스 운영비
- 활성 테이블 수와 카지노 안 NPC 수
- 플레이어의 최근 기간 실제 손익
- NPC별 외부 준비금, 오늘 외부 수입, 오늘 카지노 투입액, 오늘 총 판돈

초상은 명부 전체를 선로드하지 않고 현재 화면에 필요한 `sm` 자산 URL만 넘긴다. 선택된 게임과 상세 화면의 큰 자산은 기존 콘텐츠 로더의 지연 로딩 경계를 유지한다.

## 장기 감사 결과

현재 34 NPC 후보 계약을 동일한 씨앗으로 스트리밍 감사한 결과다. `정산 계정행`은 한 라운드의 복식부기 상대 항목을 포함하며, 사용자에게 보이는 최근 정산은 `matchId`로 묶어 실제 라운드당 한 행만 사용해야 한다.

| 기간 | 내부 공급 변화 | 실제 라운드/최근 정산 행 | 정산 계정행 | 평균 정산 간격 | 미지급 운영비 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1일 | -2.19% | 225 | 281 | 307초 | 0 P |
| 7일 | -4.49% | 931 | 1,283 | 471초 | 0 P |
| 30일 | -3.71% | 3,942 | 5,566 | 466초 | 0 P |
| 1년 | +6.87% | 46,507 | 63,364 | 498초 | 0 P |
| 10년 | +22.65% | 472,175 | 643,745 | 490초 | 0 P |

현재 실측은 출시 기준에 미달한다.

- 7일 공급 변화 `-4.49%`는 목표 `-3%~+5%` 밖이다.
- 평균 정산 간격 `307~498초`는 목표 `10~25초` 밖이다.

이는 기존 34명만으로 측정한 후보값이다. 116인 시리즈 명부에 작성 완료된 프로필을 연결한 뒤 다시 조정하며, 수치를 맞추려고 가짜 활동이나 가짜 중간 정산을 추가하지 않는다.

## 출시 게이트

1. `series-persona` 명부에서 모든 참가 NPC의 명시적 프로필을 완성한다.
2. 시리즈별 초상 매니페스트와 게임별 상대 ID가 모두 해석되는지 감사한다.
3. 7일 공급 변화 목표 `-3%~+5%`, 하우스 지급 능력, 하위 NPC 유료 참가율, 상위 5명 교체를 확인한다.
4. 1년·10년 감사에서 음수 잔고, 안전 정수 초과, 미지급 운영비 누적이 없는지 확인한다.
5. 실제 epoch과 release flag를 지정한다.
6. `pnpm check`, `pnpm test:e2e`, 프로덕션 빌드와 배포 후 라이브 테이프를 검증한다.

플레이어 전체의 손익을 하나의 공통 하우스에 합산하는 것은 서버가 생길 때까지 범위 밖이다. 지금은 NPC↔하우스가 공통 세계선이고 플레이어 거래는 브라우저별 로컬 가지다.
