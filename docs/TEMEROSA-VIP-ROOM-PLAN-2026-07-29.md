# 테메로세 VIP 룸과 제작자 제공 의상 에셋 계획

> 상태: 2026-07-29 방향 기록. 에셋 반입·VIP 공개·바카라 구현은 아직 착수하지 않았다.
> 파이브 카드 드로 맞레이즈 0.4가 완료됐으며, 이 문서는 그 뒤에 검토할 VIP 수직 시제품의 기준이다.

## 1. 제품 위치

VIP 룸은 럭키★오락실의 새 Venue가 아니라 **테메로세 카지노 안의 위층**이다. 다른 봇 IP가 럭키★오락실
로비에 독립 Venue로 들어올 수 있는 구조는 그대로 유지한다.

- 무료 도둑잡기와 현재 기본 게임을 잠그지 않는다.
- 높은 판돈과 전용 의상·딜러·연출을 제공하는 진행 목표로 둔다.
- 비어 있는 문이나 구매할 수 없는 입장권을 먼저 노출하지 않는다. 최소 한 게임이 완성된 수직 시제품과
  함께 연다.
- 시간제 출입권·일일 입장권처럼 접속 시점을 강요하는 장치는 쓰지 않는다. 첫 구현은 영구 해금 또는
  판마다 확인하는 입장 조건을 사용한다.

## 2. 확인된 원본 재고

테메로세 제작자가 팬게임 사용을 위해 직접 제공한 PNG 20장, 82,920,007바이트(79.08 MiB)다. 원본은
`C:\freetalk\테메로세`에 보관하며 저장소와 배포 루트에 그대로 복사하지 않는다.

| 구분 | 수량 | 인물·파일 | 원본 규격 |
|---|---:|---|---|
| 바니걸 | 16 | 네모 3, 바치칼 3, 박니은 4, 카노 3, 페일 3 | 1304×2312 또는 1512×2016 |
| 딜러 | 4 | **레노아 2, 이웰리스 2** | 1304×2312 또는 1512×2016 |

레노아와 이웰리스는 오너가 확정한 이름이다. 파일명의 과거 임시 이름이나 외형만으로 호스트·딜러의
세부 배역을 확정하지 않는다.

## 3. 권리와 출처 계약

- 프로젝트 오너는 제작자로부터 이 20장을 팬게임에 사용하도록 직접 제공받았으며, 기존 테메로세 에셋과
  동일한 사용·가공·내장·배포 허가 절차를 통과했다고 확인했다.
- 원본 PNG는 외부 소스다. Git에는 감사 기록·선택표·파생 WebP·매니페스트만 들어간다.
- CHARX 전용 소스 키에 억지로 끼우지 않는다. `creator-vip-2026-07-29` 같은 별도 직접 제공 소스
  계약을 만들고, 원본 파일명·바이트 해시·규격·파생 경로를 추적한다.
- 기존 정책대로 `자동 감사 → 선언 용도 선구현 승인 → 파생팩 컴파일 → 실제 화면 사후 확인` 순서를
  사용한다. 사전 육안 승인으로 절차를 되돌리지 않는다.

## 4. 배포 팩과 이미지 용도

기존 인물팩 `temerosa-margin/0.8.0`을 수정하지 않는다. 별도 지연 팩
`temerosa-vip/0.1.0`을 만들어 VIP 진입 때만 매니페스트와 필요한 이미지를 읽는다.

원본 79.08 MiB는 초기 JavaScript gzip 예산과 직접 관계가 없다. 실제 관문은 배포 용량, VIP 첫 진입
네트워크 전송량, 디코딩 메모리다. 따라서 한 원본에서 용도별 WebP만 만든다.

| 티어 | 대표 용도 | 권장 상한 | 로딩 |
|---|---|---:|---|
| `thumb` | 좌석 원형 초상·선택 목록 | 192 px | 해당 테이블 좌석 확정 뒤 |
| `table` | 딜러·호스티스 상반신/전신 연출 | 세로 768~960 px | VIP 방 진입 뒤 |
| `gallery` | 도감의 전체 구도 | 세로 1200~1600 px, 원본 초과 금지 | 상세 열람 때만 |

각 이미지는 먼저 `outfit-portrait`, `dealer-art`, `host-art`, `gallery-art` 같은 표현 용도로 승인한다.
포즈가 여러 장이라는 이유만으로 `neutral/pleased/tense/despair` 감정 슬롯에 강제 배정하지 않는다.
감정 근거가 실제 화면에서 확인된 변형만 표정 계약에 추가하며, 부족한 감정을 다른 포즈로 발명해 메우지 않는다.

## 5. 로스터 경계

네모·박니은·카노·페일은 기존 카지노 상대의 VIP 의상 변형으로 연결할 수 있다. 바치칼은 일반 카지노
좌석 풀에서 의도적으로 제외돼 있으므로, VIP 에셋을 쓴다는 이유로 기존 로스터 결정을 뒤집지 않는다.
필요하면 **VIP 전용 로스터**에만 명시적으로 포함한다.

딜러 레노아·이웰리스는 NPC 상대 풀과 별개인 진행자 역할부터 검토한다. 정본 근거 없이 대사·성격·관계를
새로 만들지 않으며, 대사가 필요하면 기존 대사 프로토콜과 원본 카드 근거 검수를 거친다.

## 6. 첫 전용 게임 후보 — 바카라

바카라는 VIP 룸의 첫 수직 시제품 **우선 후보**다. 이 기록만으로 공개나 구현을 확정하지 않는다.

선정 이유:

- VIP 룸과 문화적으로 바로 연결되고, 딜러 일러스트가 진행의 중심에 선다.
- 플레이어·뱅커·타이와 제3카드 규칙으로 순수 코어 범위가 비교적 작다.
- 카드 결과를 먼저 확정한 뒤 모서리를 천천히 여는 `스퀴즈`를 표현 계층으로 구현할 수 있다.
- `@lucky-arcade/ui/card-stage`의 카드 비행·3D 뒤집기·건너뛰기·감소 모션 규약을 재사용할 수 있다.

착수 전에 바카라 변형을 하나로 고정해야 한다. 뱅커 수수료형인지 무수수료 변형인지, 타이 배당과
하우스 엣지를 계약·화면에 공개한다. 스퀴즈 입력은 결과를 바꾸지 않으며, 결정된 카드를 보여 주는 연출만
소유한다.

## 7. 경제와 입장

- 높은 판돈은 높은 변동성을 뜻한다. 같은 선택에서 VIP라서 기대값이 몰래 좋아지지 않게 배당과 하우스
  엣지를 공개하고 회귀 테스트로 고정한다.
- VIP를 반드시 기대값 0으로 만들 필요는 없다. 포인트 소비처이므로 측정 가능한 하우스 엣지는 허용하되,
  판돈 상승과 기대값 우대를 묶지 않는다.
- 첫 입장은 업적 기반 영구 해금이나 일회성 영구 구매를 우선 검토한다. `1,000 P로 24시간` 같은 만료형
  패스는 접속 강요 원칙과 충돌하므로 사용하지 않는다.
- 전용 보상은 의상 컷·칩·덱·테이블 스킨·도감 항목을 우선한다. 기본 대사를 다시 잠그지 않는다.
- 지갑은 기존 예약·정산·환불 영수증과 동일한 복구 규율을 사용하며 NPC 원장과 합치지 않는다.

## 8. 구현 순서

1. 직접 제공 소스 계약과 출처 감사, 20장 해시 인벤토리
2. `temerosa-vip/0.1.0` 컴파일러·매니페스트·용량/MIME 감사
3. 용도별 파생본으로 VIP 게이트와 한 방의 실제 화면 수직 시제품
4. 바카라 순수 코어와 결정론·결과 해시·배당 감사
5. 카드 딜·스퀴즈·쇼다운 연출과 레노아/이웰리스 딜러 배치
6. 지갑 복구·전적·접근성·모바일 관문
7. 실제 화면 사후 확인 후 승인 에셋만 공개 팩에 유지
8. 재미가 확인된 뒤 기존 포커·블랙잭의 VIP 변형과 컬렉션을 확장

## 9. 완료 관문과 비범위

- 원본 PNG와 외부 폴더가 Git 또는 Firebase 공개 루트에 들어가지 않는다.
- VIP 팩은 기본 플로어와 일반 게임 진입에서 요청되지 않는다.
- 결과·배당·지갑 복구는 연출을 끄거나 건너뛰어도 동일하다.
- `prefers-reduced-motion`과 스퀴즈 건너뛰기를 지원한다.
- 모바일에서 딜러 그림이 조작 버튼·카드·배당 설명을 가리지 않는다.
- 바치칼의 일반 로스터 제외 결정은 변하지 않는다.

이번 기록의 비범위는 VIP 공개, 바카라 구현, 대사 집필, 감정 슬롯 확정, 전신 갤러리의 최종 노출
등급 결정이다. 이 항목들은 수직 시제품과 사후 화면 확인을 거쳐 별도 승인한다.
