# SPEC-A17 — 테메로세 카지노 자산 인벤토리

> 2026-07-26 오너 개정: 에셋 후보는 사전 육안검사를 기다리지 않는다. 자동 안전·출처·MIME·크기·경로 검사를 통과하고 오너가 선언 용도의 선구현을 승인하면 파생팩을 만들 수 있다. 실제 화면에서 크롭·의미·가독성을 확인하는 절차는 구현 뒤 반드시 수행하며, 그때까지 `postImplementationReview: pending`을 매니페스트에 남긴다. 이 개정은 아래의 기존 사전 육안 승인 문구보다 우선한다.

> 상태: v1.0 구현 계약 (2026-07-25). 코드 선행 없음. 승인 에셋을 쓰는 카지노 게임의 선행 관문이다.

## 1. 목적

원본 카드 5개·약 265MB의 이미지 재고를 카지노 게임별로 찾을 수 있는 인벤토리로 만든다. 자동 분류는
후보를 줄이는 도구이며, 안전·정본·배포 승인을 대신하지 않는다.

현재 탐색 수치 `1,826개`, `이름 필터 통과 1,592개`, 종횡비 큐 `473/314/89/122`는 출발점이지
배포 허용 목록이 아니다.

## 2. 파이프라인

```text
원본 엔트리
  → 실제 MIME·픽셀·바이트 해시
  → 이름 정규화 후보
  → 바이트 중복 묶음
  → 지각 중복 후보
  → 종횡비 작업 큐
  → 사람이 내용·SFW·시대·정본·크롭 검수
  → 게임별 명시적 허용 목록
  → 필요한 파생본만 컴파일
  → 배포 매니페스트 감사
```

## 3. 인벤토리 레코드

각 원본 엔트리는 다음 근거를 가진다.

```ts
interface CasinoAssetCandidate {
  sourceCardId: string;
  sourceEntryPath: string;
  byteHash: string;
  perceptualGroup?: string;
  detectedMime: string;
  width: number;
  height: number;
  normalizedName: { value: string; evidence: string[] };
  geometryQueue: "portrait" | "card" | "square" | "landscape" | "other";
  semanticTags: readonly string[];
  semanticStatus: "unreviewed" | "approved" | "rejected";
  appearanceSet?: string;
  approvedUses: readonly ("venue-hero" | "table-art" | "slot-symbol" | "bingo" | "bestia-target" | "collection")[];
  reviewEvidence?: string;
}
```

- `geometryQueue`는 의미 판정이 아니다. 정사각이라고 슬롯 심볼이 되지 않고, 세로라고 괴물이 되지 않는다.
- 점·언더스코어·대소문자·알려진 오타는 별칭 테이블로 정규화한다. 원본 문자열도 보존한다.
- `nieun`/`nieun_pluto`처럼 시대·외형이 다른 것은 이름이 같아도 합치지 않는다.
- 같은 파일명은 중복의 증거가 아니다. 먼저 SHA-256, 다음으로 지각 중복 후보를 만들고 사람이 최종 판정한다.

## 4. 검수와 승인

`safe`라는 상태는 만들지 않는다. 대신 승인 목적을 좁혀 기록한다.

- 이름 필터 통과는 `unreviewed`다.
- 자동 안전·출처 검사 뒤 오너가 선언 용도의 선구현을 승인하면 `approved`가 된다. 실제 화면의 SFW·인물/사물 의미·시대/외형·크롭 적합성은 `postImplementationReview`로 사후 확정한다.
- 한 용도 승인은 다른 용도로 자동 전파되지 않는다. 예: 카드 일러스트 승인이 슬롯 심볼 승인을 뜻하지 않는다.
- 원본 5개의 사용·개조·재배포 허가는 THIRD_PARTY_PROVENANCE의 동일 계약으로 연결한다.
- 오너 검수 화면은 후보 축약본만 보여 주며 원본 스크립트를 실행하지 않는다.

## 5. 첫 산출물

전체 1,592개를 굽지 않는다. 첫 릴리스는 다음만 만든다.

1. Venue 히어로 1세트: sm/md 각 1장.
2. 슬롯 수직 시제품: 승인된 정사각 후보 12~20종, 1x/2x 파생본.
3. 카지노 플로어 테이블 배경: 3~5장.

각 게임은 독립 팩 버전을 가지며 사용하지 않는 후보는 `public/`에 복사하지 않는다. 슬롯 팩은 심볼 ID,
표시명, 출처, 빈도 근거, 크롭 초점, 파일 해시를 매니페스트에 담는다.

## 6. 슬롯 배당 근거

파일 개수만으로 배당을 자동 확정하지 않는다. 재수록·크기 변형이 많아 출현 빈도가 세계관 희소성과 같지 않기 때문이다.

- 자동 빈도는 후보 자료다.
- 최종 심볼 등급은 중복 제거 뒤 실제 카드 내 출현, 원본 명칭·설명, 시각 판독성 근거를 함께 기록한다.
- 근거가 약하면 모두 같은 기본 등급으로 시작한다.
- 심볼의 의미를 새로 지어내지 않는다. 표시명은 원본 문자열 또는 검수된 번역만 쓴다.

## 7. 성능 예산

- Venue 홈 추가 이미지: 총 200KB 이하.
- 슬롯 첫 진입 필수 심볼: 총 1.5MB 이하, 실제 사용분만.
- 플로어 첫 진입: 히어로를 제외한 이미지 500KB 이하.
- 베스티아 전체 473개와 인물 전체 594개 일괄 컴파일을 금지한다.

## 8. 검증 관문

1. 모든 후보가 원본 카드·엔트리 경로·실제 MIME·크기·SHA-256을 가진다.
2. 이름 정규화가 원본을 잃지 않고 별칭 근거를 남긴다.
3. 바이트 중복과 지각 중복 후보가 구분된다.
4. `unreviewed` 항목은 어떤 배포 팩에도 들어갈 수 없다.
5. 승인 용도 밖에서 항목을 참조하면 감사 명령이 실패한다.
6. 슬롯 심볼 12~20종과 배경 3~5장만 첫 팩에 들어간다.
7. 금지 경로·실제 MIME 불일치·픽셀 상한·용량 상한을 감사한다.
8. 원본 카드와 추출 임시물이 저장소에 추가되지 않는다.

## 9. 비범위

- 1,592개 전체의 일괄 육안 검수와 배포.
- 파일명만으로 캐릭터 관계·희소도·괴물 위계를 확정하는 일.
- 피쉬 헌팅용 473종 전체 팩.
- 게임 규칙과 배당 수학.
