# SPEC-A35 — 테메로세 최애 월드컵 장기 대진

> 상태: v1.0 구현 계약 (2026-07-30). 4개 시리즈 CHARX의 유효 이미지 전량을 로컬에서 활용하고,
> 훗날 전체 사용자 인기 집계로 확장할 수 있는 투표 영수증을 남긴다.

## 1. 자산 범위

- 소스는 `overture`, `root2`, `bestiaization`, `finale` 네 시리즈다. 독립 `Nemo.charx`는 이 팩에 합치지 않는다.
- 명시적 금지 상태와 해독 불가능한 이미지만 제외한다.
- SHA-256이 같은 바이트 중복은 하나로 합친다. 지각 해시 근접 항목은 다른 표정일 수 있으므로 자동 삭제하지 않고 검토 표지만 남긴다.
- 원본 CHARX와 원본 이미지는 배포하지 않는다. 원본보다 확대하지 않은 WebP 파생본과 출처·해시 매니페스트만 배포한다.
- 한 화면은 현재 대결의 두 이미지만 불러온다. 전체 팩은 초기 로비 청크에 들어가지 않는다.

## 2. 대진 규모

`16`, `32`, `64`, `128`, `256`, `500`, `1000`, `전체`를 지원한다.

- 500장은 내부 512슬롯에 12개 부전승, 1,000장은 1,024슬롯에 24개 부전승을 배치한다.
- 우승까지 실제 선택 수는 참가 이미지 수에서 1을 뺀 값이다.
- 참가 수가 2의 제곱이 아니어도 기존 `spreadByes` 규칙으로 모든 참가자를 보존한다.
- 16·32강은 빠른 대진, 64강은 일반, 128·256강은 장기, 500·1,000·전체는 끝장 대진으로 표시한다.

## 3. 부문

- `인물전`: 정본 검수된 카지노 NPC를 같은 노출 확률로 뽑는다. 전역 인물 인기 순위의 정본 후보군이다.
- `세로 일러스트전`: 인물·베스티아를 포함한 세로형 이미지 전체. 파일 비율만으로 전부 인물이라고 추정하지 않는다.
- `아이콘·유물전`: 정사각형 이미지 전체.
- `장소·장면전`: 가로형 이미지 전체.
- `전체 이미지전`: 위 세 부문을 합친다.

이미지 수가 많은 소스가 대진을 독점하지 않도록 네 소스에서 가능한 한 같은 수를 먼저 뽑고 나머지를 결정론적으로 채운다.
같은 추정 주체의 이미지가 1회전에서 서로 만나면 뒤쪽의 다른 주체 이미지와 교환한다.

## 4. 장기 진행과 로컬 통계

- 매 선택 직후 IndexedDB에 현재 대진 스냅숏과 투표 영수증을 저장한다.
- 스냅숏에는 팩 버전, 모드, 요청 규모, 실제 참가 자산 ID, 순수 코어 상태를 둔다.
- 매니페스트에서 사라진 ID나 다른 팩 버전의 스냅숏은 복구하지 않는다.
- 화면에는 완료/전체 선택 수와 남은 선택 수를 항상 표시한다.
- 로컬 통계는 노출 수·선택 수·선택률을 분리한다. 단순 승수만으로 인기를 표시하지 않는다.

## 5. 미래 서버 계약

이번 단계에서는 네트워크 전송을 만들지 않는다. 로컬 영수증은 다음 필드를 고정한다.

```ts
interface TemerosaFavoriteVoteReceipt {
  contract: "temerosa-favorite-vote/0.1";
  voteId: string;
  seasonId: string;
  tournamentId: string;
  mode: "character" | "portrait" | "square" | "landscape" | "all";
  leftAssetId: string;
  rightAssetId: string;
  winnerAssetId: string;
  loserAssetId: string;
  round: number;
  seed: string;
  pickedAt: string;
}
```

서버 연동 시에도 포인트·카지노 전적·카드 원본·채팅·개인정보는 전송하지 않는다. 공식 순위는 노출 차이를
보정하는 Bradley–Terry 또는 Elo 계열로 계산하고, 인물 순위와 개별 이미지 순위를 분리한다.

## 6. 완료 관문

1. 같은 팩·시드·규모는 같은 참가자와 대진을 만든다.
2. 500명은 499회, 1,000명은 999회 선택으로 반드시 끝난다.
3. 정확 중복 SHA-256은 매니페스트에 한 번만 존재한다.
4. 네 소스의 참가 수 차이는 재고가 충분한 동안 최대 1이다.
5. 새로고침 뒤 선택 횟수·현재 대결·결과 해시가 동일하다.
6. 매 선택 영수증이 중복 없이 한 번만 저장된다.
7. 전체 이미지 팩은 지연 로딩되고 초기 JS gzip 200KiB 예산에 포함되지 않는다.
8. 네트워크 투표 전송은 없다.
