# SPEC-A18 — 도둑잡기 손패 제시 단계

> 상태: 구현 완료 (2026-07-26). 규칙 계약 `old-maid/0.8`.

## 목적

카드를 뽑는 행위를 즉시 판정으로 처리하지 않는다. 매 차례 뽑힐 사람이 손패를 정리해 내밀고,
정리가 끝난 뒤에만 뽑는 사람이 선택할 수 있게 한다. 플레이어·NPC·NPC끼리의 차례에 같은 규칙을 적용한다.

## 상태 계약

`offering`은 다음 세 단계를 순서대로 지난다.

1. `arranging` — 대상이 손패를 재배열한다. 플레이어 대상이면 확인 전까지 시간 제한이 없다.
2. `settling` — NPC의 재배열 결과가 화면에 착지하는 연출 구간이다.
3. `ready` — 손패를 내민 상태다. 이때만 `draw` 또는 `cpu_draw`가 유효하다.

공개 `offer` 기록에는 좌석, 단계, 재배열 횟수와 이동 인덱스만 둔다. 카드 ID·조커 위치는 넣지 않는다.
NPC의 연출 시간도 조커 보유 여부가 아니라 공개된 `lastMove` 유무로만 결정한다.

## 호흡

- 순서를 유지한 NPC 손패 제시는 약 0.6초다.
- 재배열한 손패는 이동과 착지를 포함해 약 1.2초다.
- 직접 플레이 중 NPC끼리의 구간은 기본 호흡의 75%로 압축한다.
- 관전에는 `보통`과 `빠르게`가 있으며 빠르게는 다시 65%로 압축한다.
- `prefers-reduced-motion`에서는 이동 90ms와 짧은 고정 유예만 사용한다.

시간은 화면 로컬 표현이며 저장 상태나 결과 해시에 포함하지 않는다. 탭 복귀·새로고침 뒤에는 저장된 단계에서
타이머를 다시 시작해도 같은 판정으로 이어진다.

## 입력과 연출

- 플레이어가 대상이면 손패를 최대 세 번 재배열하고 `재배열 종료 · 이대로 내밀기`로 확정한다.
- NPC 대상 손패는 결정론적으로 유지하거나 한 장을 옮긴다.
- 카드 이동은 FLIP 방식으로 이전 위치에서 새 위치까지 보여 준다. DOM을 찾지 못하거나 애니메이션 API를
  사용할 수 없어도 저장·판정은 즉시 진행한다.
- 직접 플레이의 NPC 손패는 뒷면만, 관전과 플레이어 탈락 뒤 공개 관전에서는 앞면을 보여 준다.

## 호환성과 검증

- `old-maid/0.6`과 `old-maid/0.7` 저장은 기존 즉시 뽑기 및 재배열 규칙으로 그대로 복구한다.
- 0.7 직접 플레이·관전 황금 결과 해시를 고정한다.
- 18쌍 직접 플레이와 관전 각 10,000시드가 완주해야 한다.
- 플레이어 확인 전, NPC 정돈 완료 전의 뽑기 액션은 거부한다.
- `offer` 직렬화 결과에는 카드 ID가 없어야 한다.
- 데스크톱과 390×844 화면에서 제시 손패, 확인 버튼, 관전 속도 조절이 테이블 밖으로 넘치지 않아야 한다.
