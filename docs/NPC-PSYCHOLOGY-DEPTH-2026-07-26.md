# NPC 심리 코어 심층 분석 — 무엇이 얕고 왜 그런가

> 상태: **1차 구현 완료** (2026-07-26). 분석에서 발견된 오류는 아래 구현 정정에 반영했다.
>
> 대상: [SPEC-A10](./SPEC-A10-bluffing-and-reads.md)이 배포한 심리 3층
> (`packages/engine/src/persona.ts`, `cabinets/old-maid/src/read.ts`, `engine.ts`).
>
> 이 코어는 도둑잡기 전용이 아니라 **앞으로 추가할 모든 테이블 게임이 공유**한다. 여기서 깊어지면 전부 깊어진다.

## 0. 구현 정정과 착지 결과

- 상시 표정은 `OldMaidState.reactions`를 덮어쓰지 않고 순수 selector로 파생한다. 따라서 기존 저장 해시를 바꾸지 않는다.
- `readAccuracy`를 바로 삭제하지 않고 기존 게임 호환 필드로 보존했다. 새 도둑잡기 정책은 `signalAttention`과 부호 있는 `signalTrust(-1..1)`를 사용한다.
- open은 재배열 신호를 문자 그대로 읽고, guarded는 미끼로 의심하며, standard는 근거가 없어 신호를 거의 사용하지 않는다. `riskAppetite`는 카드 위치 조준에서 제거했다.
- 이름 해시로 확장 NPC 성격을 발명하던 코드는 제거했다. 정본 근거가 없는 NPC는 `standard`를 쓴다. 단, 저장된 0.6 대국의 해시 재현을 위해 0.6 리듀서 경로에서만 옛 파생식을 보존한다.
- CPU 재배열은 작은 무계약 변경이 아니었다. 0.7 상태에 좌석별 `lastReorders`를 선택 필드로 추가하고, 0.6 상태는 옛 정책과 상태 모양을 그대로 유지한다.
- 0.6 스냅숏은 0.6 정책으로 계속 플레이되고 재시작부터 0.7로 올라간다. 진행 중인 대국을 폐기하지 않는다.
- `손패가 적은 좌석은 조커 보유 확률이 높다`는 5절 B-3의 설명은 잘못이다. 추가 정보가 없다면 좌석의 조커 보유 확률은 손패 장수에 비례한다. 자유 표적 선택은 별도 하우스 룰로 계속 보류한다.
- 재배열·관찰·미끼 결과는 게임 판정 상태가 아닌 로컬 심리 요약으로 기록하고 완료 전적의 선택 필드에 붙인다.

## 1. 무엇이 잘 됐는가

먼저 유지해야 할 것을 명확히 한다. 아래는 건드리지 않는다.

- **부정행위가 구조적으로 불가능하다.** `publicRead`의 반환값에 카드 ID가 하나도 없고 손패 *길이*만 본다.
  상대 패를 보는 AI는 강한 게 아니라 부정행위라는 원칙이 타입으로 강제돼 있다.
- **결정론이 유지된다.** `weightedChoice`가 시드당 난수를 정확히 한 번 소비한다.
- **`packages/engine`이 게임을 모른다.** `persona.ts`에 도둑잡기 어휘가 없어 인디언 포커가 그대로 재사용한다.
- **재배열 신호의 시간축이 정확하다.** `reorderedSinceTargetDraw`가 `이번 턴`이 아니라
  `그 손에서 다음 카드를 뽑힐 때까지` 유지된다. 명세 초안의 오류를 구현에서 바로잡은 것이다.

## 2. 근본 원인 — 결정 공간이 1차원이고 그 차원에 정보가 없다

```ts
const targetId = nextActiveSeat(state.hands, actorId);   // engine.ts:74 — 표적은 강제
const index = cpuDrawIndex(...);                          // engine.ts:78 — 유일한 결정
```

CPU가 내리는 결정은 **`몇 번째 카드`** 하나뿐이다. 그런데 뒷면 카드는 CPU 입장에서 전부 동일하다.
구별자가 존재하지 않는다.

따라서 `publicRead`가 돌려주는 `targetHandSize`·`targetDiscardCount`·`turnsSinceTargetDrew`를
가중치에 쓰지 않은 것은 **누락이 아니다. 쓸 곳이 없다.** 상대 손패가 8장이든 2장이든
`3번째 카드`를 고를 이유는 달라지지 않는다.

유일하게 의미를 갖는 신호가 **위치 정보(재배열)** 뿐인 이유가 이것이다.

> **관측을 늘리는 것으로는 깊어지지 않는다.** 결정 공간을 넓히거나, 관측을 다른 출력(표정)에 쓰거나,
> 규칙을 열어야 한다.

## 3. 발견된 결함 — 성격이 셋이 아니라 둘이다

```
만진 자리 배수 = 1 + readAccuracy × riskAppetite × 1.4
```

| tellStyle | read × risk | 배수 | 4장 중 선택 확률 |
|---|---|---|---|
| `open` | 0.50 × 0.50 = **0.250** | ×1.350 | **31.0%** |
| `guarded` | 0.70 × 0.35 = **0.245** | ×1.343 | **30.9%** |
| `bluffer` | 0.60 × 0.70 = 0.420 | ×1.588 | 34.6% |

**`open`과 `guarded`의 선택 확률 차이가 0.1%p다.** 두 성격이 사실상 같은 행동을 한다.

원인은 **곱**이다. `잘 읽지만 소극적`과 `덜 읽지만 적극적`이 서로 상쇄된다.
`riskAppetite`가 조준 강도에 직접 곱해지는 구조인 한 이 상쇄는 계속된다.

흔들림 폭만 다르다 — `(1 - consistency) × 0.35` → open ±5.3%, guarded ±10.5%, bluffer ±19.3%.
즉 **방향성은 두 종류, 노이즈만 세 종류**다.

### 회귀 테스트가 없어서 놓쳤다

이 결함은 단위 테스트로 잡혔어야 한다. 지금 테스트는 결정론·범위·난수 횟수만 본다.
**성격이 서로 구별되는지를 검사하지 않는다.**

→ 아래 9절에 그 테스트를 제안한다.

## 4. 갈래 A — 표정 연속화 (규칙 변경 0, 이득 최대)

### 현재

`reactions`가 갱신되는 지점이 코어 전체에서 **두 곳**뿐이다.

```
engine.ts:25   초기화 — 전원 neutral
engine.ts:88   reactionsAfterDraw — 뽑기 순간, actor와 target 두 좌석만
```

나머지 좌석의 표정은 **이전 값이 그대로 남는다.** 게임 대부분의 시간 동안 화면의 얼굴이 낡은 값이다.
플레이어가 읽을 정보가 뽑기 순간에만 존재한다.

그리고 truth 입력이 두 개뿐이다.

```ts
drewJoker ? "tense" : madePair ? "pleased" : "neutral"   // 행위자
drewJoker ? "pleased" : "neutral"                        // 대상
```

### 코어가 이미 아는데 표정에 안 쓰이는 사실

전부 `OldMaidState`에서 즉시 파생된다. 새 필드가 필요 없다.

```
holdsJoker         내가 조커를 들고 있다
handSize           내 손패 크기
aboutToEmpty       한 장 남았다 — 짝이 되면 탈출
jokerJustArrived   방금 조커가 내 손에 들어왔다
jokerJustLeft      방금 조커가 내 손에서 나갔다
amNextVictim       다음 차례에 내 손에서 뽑힌다
safeCount          이미 손을 비운 좌석 수 — 압박
```

**실제 도둑잡기에서 가장 긴장되는 순간 — `곧 내 손에서 뽑히는데 나는 조커를 들고 있다` — 이것이
지금 표정에 전혀 나타나지 않는다.**

### 제안

`reactionsAfterDraw(...)`를 `reactionsFor(cartridge, state)`로 바꾸고 **매 상태 전이마다 전 좌석**의
truth를 재계산한다. persona 필터(`expressSignal`)는 그대로 쓴다.

얻는 것:

- 표정이 게임 내내 살아 있다. 읽을 것이 상시 존재한다.
- **A10의 관찰 예산 3장 제한이 그제야 의미를 갖는다.** 지금은 볼 것이 없어 예산이 남는다.
- 규칙·계약·저장 변경이 **없다.** 파생 함수 하나를 바꾼다.

## 5. 갈래 B — 결정 공간을 연다 (규칙 변경)

### B-1. CPU도 손패를 섞게 한다

지금 재배열은 `assert(isHuman, ...)`로 플레이어 전용이다(engine.ts:63). CPU에게 열면:

- 조커를 막 받은 `open` 성격이 섞으면 **티가 난다** — 플레이어가 읽을 새 신호
- `bluffer`는 아무 때나 섞어 노이즈를 만든다
- `guarded`는 거의 섞지 않는다

**심리전이 양방향으로 완성된다.** 지금은 플레이어만 속일 수 있고 CPU는 속이지 못한다.

실제 구현에서는 단순한 `isHuman` 완화로 끝나지 않았다. 기존 `lastReorder`는 플레이어 한 명만
기록하므로 좌석별 `lastReorders`가 필요했고, CPU가 뽑기·짝 버리기를 끝낸 뒤 섞는 결정론적 자동 전이를
추가했다. 0.6에는 적용하지 않고 0.7 신규 대국부터 사용한다.

### B-2. 짝을 보류할 수 있게 한다

지금 짝은 즉시 버림이 강제다. 보류를 허용하면:

- **손패 크기를 위장**할 수 있다. 남들은 `쟤 아직 8장이네`라고 오판한다.
- 대가: 손이 줄지 않아 탈출이 늦고 조커를 받을 기회가 늘어난다.
- 위험 대 보상이 명확한 진짜 선택이다.

부수 효과가 더 크다 — **`targetHandSize`가 처음으로 거짓말할 수 있게 된다.**
지금은 손패 크기가 100% 진실이라 읽을 가치가 없다. 보류가 생기면 관측에 의미가 붙는다.

### B-3. 표적 선택

`nextActiveSeat` 강제를 풀면 `누구에게서 뽑을까`가 결정이 된다. 그러면 세 관측값이
**드디어 쓸 곳**을 얻는다. 단, 추가 정보가 없다면 조커 보유 확률은 손패 장수에 비례하므로
`손패가 적을수록 조커 확률이 높다`고 볼 수 없다. 버림 이력·표정·재배열 신호를 함께 해석해야 한다.

다만 정통 도둑잡기는 옆 사람에게서 뽑는다. **하우스 룰 변형 테이블**로 두는 것이 맞다.
카지노 안이므로 테이블마다 규칙이 다른 것이 오히려 자연스럽다.

## 6. 갈래 C — 그냥 빠진 것

### C-1. `lastReorder.count`가 저장되는데 읽히지 않는다

```ts
lastReorder: { turn, toIndex, count }        // contracts.ts — count 저장됨
publicRead → { ..., reorderIndex }           // read.ts — count 없음
```

세 번 섞은 사람은 한 번 섞은 사람보다 숨기는 것이 많다. **한 줄 추가로 신호가 하나 늘어난다.**

### C-2. 재배열 타이밍이 읽히지 않는다

조커를 받은 **직후에** 섞었는지는 강력한 단서다. 사람이 실제로 읽는 것이 이것이다.
`lastReorder.turn`과 그 좌석의 마지막 draw 턴을 비교하면 파생된다. 새 필드가 필요 없다.

## 7. 균형 — `더 세게`는 틀린 답이다

재배열과 노림은 **matching pennies** 구조다.

- CPU가 항상 만진 자리를 노리면 → 플레이어가 **미끼**를 놓는다(안전 카드를 옮긴다)
- CPU가 무시하면 → 재배열이 무의미해진다
- **혼합 전략이 균형**이며, 그 관점에서 현재 1.59배는 나쁜 값이 아니다

필요한 것은 세기가 아니라 **성격별 분화**다.

### 제안 — 5번째 축 `counterRead` (역읽기)

```
낮음   만진 자리를 곧이곧대로 노린다          페일 · 리엘 · 바치칼   (open)
중간   반반                                    카노 · 알제
높음   미끼를 의심해 오히려 양옆을 노린다      라일라 · 박니은        (통제형)
```

- 플레이어가 **`이 사람에겐 미끼가 통하고 저 사람에겐 안 통한다`** 를 학습하게 된다.
- 상대별 전적(A8)과 맞물려 `라일라와 12판 중 3승`이 실제 이유를 갖는다.
- **3절의 open/guarded 미분화가 이 축으로 해소된다.** 조준 강도를 `readAccuracy` 단독으로 두고,
  `riskAppetite`는 다른 곳(짝 보류·판돈 등)에 쓰면 상쇄가 사라진다.

인물 배정은 대사집(`TEMEROSA-OLD-MAID-DIALOGUE.md`)의 화법 해석과 일치시킨다.
라일라의 `통제 가능한 범위 안이야`, 니은의 `모든 분기를 계산했어`가 곧 역읽기 성향이다.

## 8. 우선순위와 계약 영향

| # | 항목 | 계약 상승 | 규모 | 이득 |
|---|---|---|---|---|
| 1 | 상태 밖 상시 표정 selector (A) | **없음** | 중 | **최대** — 읽을 것이 상시 존재 |
| 2 | `count`·타이밍 갭 (C) | 규칙 0.7 | 소 | 신호 2개 추가 |
| 3 | `signalTrust` 축 (7절 보정) | 규칙 0.7 | 소 | 미분화 해소 + 균형 유지 |
| 4 | CPU 재배열 (B-1) | 상태 선택 필드 + 규칙 0.7 | 중 | 심리전 양방향 완성 |
| 5 | 짝 보류 (B-2) | **있음** | 중 | 손패 크기가 거짓말 가능 |
| 6 | 표적 선택 (B-3) | **있음** | 대 | 관측 셋이 쓸 곳을 얻음 |

상태 스키마와 결정론 규칙 버전을 구분한다. 1은 저장·결과 해시에 닿지 않지만, 2·3은 같은 입력의
CPU 선택을 바꾸므로 규칙 0.7로 구분해야 한다. 0.6 저장 대국은 옛 정책으로 끝까지 재생한다.

**5·6은 계약이 오른다.** 카지노 개편에서 한꺼번에 묶는 것이 폐기 횟수를 줄인다.

## 9. 검증 방법

심리의 깊이는 테스트하기 어렵다. 아래는 실제로 검사 가능한 것들이다.

### 반드시 유지

1. **결정론** — 같은 시드·입력이 같은 결과 해시를 만든다.
2. **10,000시드 종료** — 무한 루프·패자 부재 0.
3. **부정행위 차단** — `publicRead` 반환값에 카드 ID가 없다.
4. **난수 1회** — `weightedChoice`가 시드당 한 번만 소비한다.

### 새로 추가할 것

5. **성격 구별성** — 세 프리셋의 선택 분포가 통계적으로 구별된다.
   같은 상황 1,000시드에서 `만진 자리 선택률`이 성격마다 유의하게 달라야 한다.
   **이 테스트가 있었다면 3절의 결함을 잡았다.** 지금 코드는 이 테스트에서 실패한다.
6. **표정 생동성** — 한 판에서 뽑기에 관여하지 않은 좌석의 표정도 변한다.
   현재 코드는 실패한다(변하지 않는다).
7. **역읽기 대비** — `counterRead`가 높은 성격과 낮은 성격의 만진 자리 선택률이 **반대 방향**이다.
8. **관찰 예산 소진** — 표정이 상시 갱신되면 3장 예산이 실제로 부족해지는지 실측한다.
   남아돌면 예산 제한이 무의미하다는 뜻이다.

### 재미 관문

전적(A8) 데이터로 판단한다.

- 상대별 승률이 인물마다 **실제로 갈리는가.** 지금은 갈릴 이유가 거의 없다.
- 재배열 사용 횟수가 판을 거듭하며 **늘어나는가.** 늘지 않으면 플레이어가 그 수단을 무용하다고 판단한 것이다.

## 10. 다른 게임으로의 전이

`persona.ts`는 게임을 모르므로 아래 개선이 그대로 따라간다.

- **인디언 포커** — `counterRead`가 `상대의 표정을 믿을지 의심할지`가 된다. 표정이 유일한 정보인 게임이라 효과가 가장 크다.
- **홀덤·다우트** — `riskAppetite`가 조준에서 풀려나 **베팅 크기**라는 제 자리를 찾는다.
  현재 도둑잡기에서 그 축이 조준에 곱해진 것이 애초에 부자연스러웠다.
- **표정 연속화**는 좌석이 있는 모든 테이블에 적용된다.

즉 4절·7절은 도둑잡기 개선이 아니라 **카지노 전체의 기반 개선**이다.

## 11. 후속 구현 — 손패 제시 단계 (2026-07-26)

4절의 CPU 재배열은 규칙 `0.8`에서 뽑기 뒤의 암묵 동작이 아니라 다음 사람이 뽑기 전 반드시 거치는
`arranging → settling → ready` 단계로 승격했다. 플레이어·NPC·NPC끼리 모두 같은 단계에 들어가며,
플레이어 대상일 때만 명시적 확인 버튼까지 시간 제한 없이 기다린다.

세부 계약과 호흡은 [SPEC-A18](./SPEC-A18-old-maid-hand-offering.md)을 정본으로 삼는다. 0.6·0.7 저장과
결과 해시는 종전 경로로 보존한다.
