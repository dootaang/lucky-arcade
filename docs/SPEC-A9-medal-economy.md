# SPEC-A9 — 메달 경제

> 상태: v1.1 구현 완료 (2026-07-25).
>
> **선행: [SPEC-A8](./SPEC-A8-match-history.md)이 먼저 착지해야 한다.** 지급 멱등 규칙이 전적 기록과
> 같은 키(`${sessionId}#${sequence}`)를 쓰고, 같은 완료 전이 지점에서 동작한다.

## 1. 목적과 관문

BACKLOG는 공용 재화를 **"파산 방지·초기 자본·되돌릴 수 없는 소비·저장 복구 규칙을 먼저 확정한다"**는
조건으로 묶어 두었다. 이 문서가 그 계약이다.

도둑잡기 등수에 값을 매기고, 그 값을 쓸 곳을 같이 연다. **버는 곳만 만들고 쓰는 곳을 안 만들면
메달은 두 번째 점수판일 뿐이다.** 그래서 지갑과 소비처를 한 번에 낸다.

## 2. 화폐

- 단위는 **메달**, 아이콘은 **★**, 표기는 `★1,240`이다.
- 오락실 메달게임 은유가 정확하고, **현금화되지 않는 놀이 화폐**라는 문화적 합의가 이미 있어 도박 어감이 낮다.
- 세계관 중립이다. 테메로세·소녀전선·개인 카드 어디에도 묶이지 않는다.
- 초기 자본 **★100**.

## 3. 설계 결정과 근거

| 결정 | 근거 |
|---|---|
| 지갑을 게임 상태 밖 별도 스토어에 둔다 | 스냅숏에 넣으면 재시작·복구에서 복제되거나 사라진다 |
| 세션별 **최고 지급 시퀀스**로 멱등을 잡는다 | 완료 화면은 이어하기로 다시 열린다. 재지급되면 새로고침만으로 무한 파밍이다 |
| 잔액을 따로 저장하고 원장을 합산하지 않는다 | 원장을 정리하는 순간 합산 잔액이 틀어진다. 잔액 갱신과 지급 기록은 **한 트랜잭션**에서 처리한다 |
| 제로섬이 아니라 완만한 인플레로 간다 | 도둑잡기는 운 비중이 커 실력차가 작다. 제로섬이면 모두 0으로 수렴해 화폐가 플레이 카운터가 된다 |
| 참가 보상을 성적과 분리한다 | 꼴찌 손실이 실질 −4로 줄어 파산이 사실상 불가능해진다 |
| 회복을 **잔액 기준**으로 하고 시간 기준으로 하지 않는다 | ROADMAP 순화 원칙이 `일일 과제 → 고정 시드 도전, 접속 강요 없음`을 못 박았다 |
| 소비처를 **확정 신규 개봉**으로 한다 | 같은 원칙의 `뽑기 → 플레이로 발견한 것의 개봉 연출(중복 없는 확정 신규)` 지시다 |
| 관전 판은 지급하지 않는다 | 플레이어가 참여하지 않은 판이다 |

## 4. 지급표

```
참가 완주   +2      중도 이탈은 없음. 완료 전이에서만 지급
1등        +10
2등         +5
3등         +1
꼴찌        −6
```

- 기대값은 판당 **+4.5**다.
- **잔액은 0 미만으로 내려가지 않는다.** 차감은 잔액까지만이다.
- **잔액이 20 미만이면 참가 보상이 +6이 된다.** 접속 시각과 무관하게 회복된다.
- 등수는 A8의 `oldMaidOutcome`이 만든 순위를 그대로 쓴다. 별도 판정을 만들지 않는다.
- 관전 모드(`outcome === "spectated"`)는 지급 0이며 원장에도 남기지 않는다.

## 6. 금지사항

1. **`engine.ts`·`OldMaidState`를 수정하지 않는다.** 경제는 게임 규칙 밖이다.
2. **판돈·베팅을 만들지 않는다.** 도박 어감이 급상승하고 파산 방지 규칙과 정면으로 싸운다. 비범위다.
3. **시간 기반 지급·일일 보상·연속 접속 보상을 만들지 않는다.**
4. **잔액을 스냅숏이나 `RecentPlay`에 넣지 않는다.**
5. **원장 합산으로 잔액을 계산하지 않는다.** 정리와 함께 틀어진다.
6. **지급 실패가 대국을 막지 않는다.** 결과 화면은 그대로 뜬다.
7. **확률형 개봉을 만들지 않는다.** 개봉은 항상 미보유 항목이며 중복이 나오지 않는다.
8. **메달을 서버로 보내거나 공유 코드에 담지 않는다.**

## 7. 계약

`packages/persistence`에 둔다.

```ts
export interface WalletSnapshot {
  contract: "wallet/0.1";
  id: "wallet";
  balance: number;          // 0 이상
  updatedAt: string;
}

export interface MedalGrant {
  contract: "medal-grant/0.1";
  sessionId: string;        // 키
  highestSequence: number;  // 이 세션에서 지급을 마친 가장 높은 시퀀스
  updatedAt: string;
}

export interface WalletStore {
  read(): Promise<WalletSnapshot>;                 // 없으면 초기 자본으로 만든다
  grant(input: MedalGrantInput): Promise<WalletSnapshot>;
}

export interface MedalGrantInput {
  sessionId: string;
  sequence: number;
  cabinetId: string;
  rank: number;             // 1부터
  seatCount: number;
  spectated: boolean;
}
```

### 멱등

`grant`는 **한 트랜잭션**에서 다음을 수행한다.

```
grants[sessionId].highestSequence >= sequence  →  아무것도 하지 않고 현재 잔액 반환
그 외 →  잔액 갱신 + highestSequence 갱신을 함께 커밋
```

`restart`는 시퀀스를 증가시키므로 같은 세션에서 다시 완주하면 정상 지급된다.
완료 화면을 새로고침으로 다시 열면 시퀀스가 같으므로 지급되지 않는다.

원장을 따로 쌓지 않는다. 세션당 한 행이므로 무한히 늘지 않고, 정리도 필요 없다.
지급 이력은 A8의 전적 기록이 이미 가지고 있다.

## 8. 소비처 — 도감

**메달만 만들고 쓸 곳을 안 만드는 것을 금지한다.** 같은 릴리스에 넣는다.

- 대상은 현재 카트리지의 `faces` 전체다. 테메로세는 58종, 개인 카드는 그 카드의 얼굴 수만큼이다.
- **개봉 비용은 ★12 고정이다.** 초기 자본으로 8장을 열 수 있고, 이후에는 약 3판에 1장 속도다.
- 개봉은 **항상 미보유 항목 중 하나**다. 확률도 중복도 없다. 어떤 것이 나올지는 시드로 정해진다.
- 미보유 항목은 실루엣으로 보이고 이름이 가려진다. 개봉하면 얼굴과 이름이 열린다.
- 전부 개봉하면 개봉 버튼이 사라진다. **다음 소비처는 그때 판단한다.** 지금 만들지 않는다.
- 개봉 상태는 카트리지 버전이 아니라 **얼굴 ID**로 저장한다. 팩이 올라가도 보유분이 유지된다.
- 개인 카드 도감은 `cardFingerprint`로 분리한다. 다른 카드의 보유분과 섞지 않는다.

**구현 정정:** 개봉의 메달 차감과 얼굴 해금도 지급과 같은 원자성 규칙을 적용한다. 두 작업을
`wallet + collection` 단일 IndexedDB 트랜잭션에서 커밋해 공짜 해금과 메달만 사라지는 실패를 막는다.

화면은 결과 화면과 로비에서 진입하는 **모달 그리드**로 만든다. 사이드바 라우팅은 비범위다.

## 9. 화면

- 도둑잡기 헤더 우측에 `★1,240`. 이미 있는 `자동 저장됨` 표시 옆이다.
- 결과 화면에 증감 한 줄: `+10 · 1등`. 관전 판은 표시하지 않는다.
- 로비에 잔액 한 줄.
- **새 `aria-live` 영역을 만들지 않는다.** 잔액 변화는 결과 화면 텍스트로 전달된다.
- 잔액이 20 미만이면 결과 화면에 `참가 보상이 늘어난 상태입니다` 한 줄을 덧붙인다. 구걸 문구를 쓰지 않는다.

## 10. 테스트 관문

1. **초기 자본** — 지갑이 없으면 ★100으로 만들어진다.
2. **지급표** — 1/2/3/꼴찌 + 참가가 표대로 계산된다.
3. **멱등** — 같은 `(sessionId, sequence)`로 두 번 지급하면 잔액이 한 번만 변한다.
4. **재시작 지급** — 시퀀스가 오르면 다시 지급된다.
5. **하한** — 잔액 3에서는 회복 참가 보상 `+6`과 꼴찌 `−6`이 상쇄되어 잔액 3을 유지한다.
6. **회복** — 잔액 19에서 참가 보상이 +6이고, 20에서는 +2다.
7. **관전 제외** — `spectated`는 잔액을 바꾸지 않고 `highestSequence`도 올리지 않는다.
8. **트랜잭션** — 지급 도중 실패하면 잔액과 `highestSequence`가 함께 롤백된다.
9. **도감 확정 신규** — 100회 개봉에서 중복이 0이고, 잔여 0이면 개봉이 거부된다.
10. **도감 분리** — 서로 다른 `cardFingerprint`의 보유분이 섞이지 않는다.
11. **잔액 부족** — ★11에서 개봉이 거부되고 잔액이 그대로다.

## 12. 비범위

- **판돈·베팅·배수 선택** — 도박 어감과 파산 방지가 충돌한다. 별도 관문.
- **캐비닛 간 시세·상점·강화** — 소비처 하나의 반응을 먼저 본다.
- **도감 외 소비처** — 전부 개봉이 가까워졌을 때 판단한다.
- **사이드바 `기록`·`도감` 라우팅** — 지금 사이드바 항목은 전부 장식이다.
- **다른 캐비닛 지급** — 계약은 범용으로 두되 v1은 도둑잡기 두 종만 쓴다.
