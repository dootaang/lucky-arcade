# SPEC-A13 — 포인트 경제 개정

> 상태: v1.0 구현 계약 (2026-07-25). **[SPEC-A9](./SPEC-A9-medal-economy.md)를 대체한다.**
> A9의 지급 멱등·트랜잭션 경계·도감 연결은 그대로 살리고, 화폐 이름과 경제 구조만 갈아낀다.
>
> 근거: ROADMAP `무료 경제 원칙`, PRODUCT-MEMORY `경제 해금 이후 기억할 것` (둘 다 2026-07-25 오너 결정).

## 1. A9에서 무엇이 바뀌는가

| 항목 | A9 (배포됨) | A13 (이 문서) |
|---|---|---|
| 화폐 이름 | 메달 ★ | **포인트 P** |
| 초기 자본 | ★100 | **없음** |
| 파산 방지 | 0 하한 + 잔액 20 미만 시 보상 증액 | **없음. 무료 테이블이 대신한다** |
| 판돈 | 금지 | **정식 메커니즘** |
| 지급 | 등수별 고정액 | **판돈 배수(제로섬) + 무료 완주 보상** |
| 입장 | 개념 없음 | `free` · `wager` · `both` 선언 |

**개정 이유.** A9는 무작위성과 판돈을 순화 원칙의 금지 대상으로 잘못 분류했다. 그 원칙이 겨냥하는 것은
**현금 지출과 접속 강요**다. 무료·로컬·폐쇄 루프에서 판돈은 해악이 아니라 **선택에 무게를 싣는 장치**이며,
표정을 읽을 이유가 거기서 처음 생긴다. 판돈을 빼면 카드게임은 얕아질 뿐이다.

## 2. 화폐

- 단위 **포인트**, 표기 `1,240 P`. 커뮤니티 어휘를 그대로 쓴다.
- **초기 자본이 없다.** 0에서 시작해 무료 테이블에서 번다.
- 아이콘을 쓴다면 `P`이며 ★는 쓰지 않는다. ★는 브랜드 표식이지 화폐 기호가 아니다.

## 3. 무료 입장 수익원 구조

**파산 구제 로직을 만들지 않는다.** 대신 **언제나 열려 있는 무료 테이블**을 둔다.

```
무료 테이블(도둑잡기)    →  포인트 획득
        ↓
판돈 테이블              →  포인트 증감
        ↓
뽑기·도감·덱 스킨        →  다시 플레이할 이유
```

포인트가 0이어도 앉을 자리가 항상 있으므로 **막다른 상태가 구조적으로 없다.** 조건 분기로 막는 것이
아니라 구조로 막는 것이 핵심이다.

### 입장 선언

`CabinetManifest`에 추가한다. 앱 셸에 게임별 분기를 만들지 않는다.

```ts
entry: "free" | "wager" | "both";
wagerTiers?: readonly number[];   // both·wager일 때 고를 수 있는 판돈
```

| 캐비닛 | entry | 판돈 |
|---|---|---|
| 테메로세 도둑잡기 | `both` | 0 · 10 · 50 · 200 |
| 내 카드 도둑잡기 | `both` | 0 · 10 · 50 · 200 |
| 인디언 포커 | `wager` | 10 · 50 · 200 |
| 최애 월드컵 · 기억 게임 | `free` | — |

## 4. 지급

### 무료 판

```
완주 보상   +5 P    등수 무관, 접속 무관
```

총량 성장은 전부 여기서 나온다. 판돈 판은 제로섬이라 총량을 늘리지 않는다.

### 판돈 판 — 완전 제로섬

```
1등   +1.5 × 판돈
2등   +0.5 × 판돈
3등   −0.5 × 판돈
꼴찌  −1.5 × 판돈        합계 0
```

- 판돈 50이면 1등 +75, 꼴찌 −75다.
- 판돈 판에도 완주 보상 +5를 함께 준다. 참여 자체는 손해가 아니어야 한다.
- **좌석 수가 4가 아닌 게임은 배수표를 별도로 선언한다.** 합이 0이 되도록 맞춘다.
- 관전 모드는 판돈을 걸 수 없다. `entry`와 무관하게 무료이며 완주 보상도 없다.

### 잔액 검사

- 판돈 선택 화면에서 **잔액보다 큰 판돈은 고를 수 없다.** 고른 뒤 모자라는 상황을 만들지 않는다.
- 잔액이 최저 판돈 미만이면 판돈 좌석이 잠기고 무료 좌석만 열린다. 안내는 한 줄이면 된다.
- **차감은 판 시작이 아니라 완료 시점에 정산한다.** 중도 이탈 시 잃는 것이 없어야 이어하기 원칙과 맞는다.

## 6. 이관

**배포된 지갑이 이미 있다.** 잔액을 버리지 않는다.

- `INITIAL_MEDAL_BALANCE = 100`으로 만들어진 기존 잔액은 **그대로 포인트로 이관**한다. 1:1이다.
- 스토어 키와 멱등 기록(`highestSequence`)은 유지한다. 재지급이 발생하면 안 된다.
- 개명은 표기와 식별자에만 적용한다. **이관 중 잔액이 0이 되는 경로를 만들지 않는다.**

## 7. 금지사항

1. **현금 구매·환전·외부 거래 경로를 만들지 않는다.** 포인트는 플레이로만 얻는다.
2. **접속 기반 보상을 만들지 않는다.** 일일 지급·연속 출석·시간 제한 이벤트 금지. 주기가 필요하면 **판수 기반**으로 한다.
3. **포인트를 서버로 보내거나 공유 코드에 담지 않는다.**
4. **실제 금전 가치를 시사하는 표현을 쓰지 않는다.**
5. **초기 자본·파산 구제 로직을 만들지 않는다.** 무료 테이블이 그 역할이다.
6. **`engine.ts`·게임 상태를 수정하지 않는다.** 판돈은 게임 규칙 밖의 정산이다.
7. **판돈이 판정·배분·표정에 영향을 주지 않는다.** 같은 시드면 판돈과 무관하게 같은 결과다.
8. **기존 잔액을 초기화하지 않는다.**

## 8. 테스트 관문

1. **개명 이관** — 기존 메달 잔액 100이 포인트 100으로 남는다.
2. **초기 자본 없음** — 새 사용자의 잔액이 0이다.
3. **무료 완주** — 잔액 0에서 무료 판을 끝내면 +5가 된다.
4. **제로섬** — 4좌석 배수 합이 정확히 0이다. 판돈 10·50·200 전부에서.
5. **판돈 상한** — 잔액보다 큰 판돈을 고를 수 없다.
6. **잠금** — 잔액이 최저 판돈 미만이면 판돈 좌석이 잠기고 무료 좌석은 열린다.
7. **멱등** — 같은 `(sessionId, sequence)` 정산이 두 번 반영되지 않는다.
8. **관전 제외** — 관전 판은 잔액을 바꾸지 않는다.
9. **중도 이탈** — 판 도중 이탈하면 잔액이 그대로다.
10. **판정 불변** — 같은 시드에서 판돈만 바꿔도 `resultHash`가 같다.

E2E

11. 잔액 0에서 무료 도둑잡기를 완주하면 포인트가 생긴다.
12. 그 포인트로 판돈 판을 열 수 있다.
13. 새로고침 후 이어하기로 돌아와도 잔액이 그대로다.
