# SPEC-A13 — 포인트 경제 개정

> 상태: v1.2 구현 계약 (2026-07-26). **[SPEC-A9](./SPEC-A9-medal-economy.md)를 대체한다.**
> A9의 지급 멱등·트랜잭션 경계·도감 연결은 그대로 살리고, 화폐 이름과 경제 구조만 갈아낀다.
>
> 근거: ROADMAP `무료 경제 원칙`, PRODUCT-MEMORY `경제 해금 이후 기억할 것` (둘 다 2026-07-25 오너 결정).

## 1. A9에서 무엇이 바뀌는가

| 항목 | A9 (배포됨) | A13 (이 문서) |
|---|---|---|
| 화폐 이름 | 메달 ★ | **포인트 P** |
| 초기 자본 | ★100 | **없음** |
| 파산 방지 | 0 하한 + 잔액 20 미만 시 보상 증액 | **없음. 무료 테이블이 대신한다** |
| 판돈 | 금지 | **정식 메커니즘** |
| 지급 | 등수별 고정액 | **판돈 배수 + 무료 완주 보상** |
| 경제 모드 | 개념 없음 | `free` · `wager` · `mixed` 선언 |

**개정 이유.** A9는 무작위성과 판돈을 순화 원칙의 금지 대상으로 잘못 분류했다. 그 원칙이 겨냥하는 것은
**현금 지출과 접속 강요**다. 무료·로컬·폐쇄 루프에서 판돈은 해악이 아니라 **선택에 무게를 싣는 장치**이며,
표정을 읽을 이유가 거기서 처음 생긴다. 판돈을 빼면 카드게임은 얕아질 뿐이다.

## 2. 화폐

- 단위 **포인트**, 표기 `1,240 P`. 커뮤니티 어휘를 그대로 쓴다.
- **초기 자본이 없다.** 0에서 시작해 무료 테이블에서 번다.
- 아이콘을 쓴다면 `P`이며 ★는 쓰지 않는다. ★는 브랜드 표식이지 화폐 기호가 아니다.

## 3. 무료 입장 수익원 구조

**파산 구제 로직을 만들지 않는다.** 대신 **언제나 열려 있는 무료 테이블**을 둔다.

```
무료 테이블(도둑잡기)    →  포인트 획득
        ↓
판돈 테이블              →  포인트 증감
        ↓
뽑기·도감·덱 스킨        →  다시 플레이할 이유
```

포인트가 0이어도 앉을 자리가 항상 있으므로 **막다른 상태가 구조적으로 없다.** 조건 분기로 막는 것이
아니라 구조로 막는 것이 핵심이다.

### 경제 모드 선언

`CabinetManifest`에 추가한다. `entry`는 화면 진입점과 혼동되므로 쓰지 않는다. 앱 셸에 게임별 분기를 만들지 않는다.

```ts
economy: {
  mode: "free" | "wager" | "mixed";
  wagerTiers?: readonly number[];
};
```

| 캐비닛 | mode | 판돈 |
|---|---|---|
| 테메로세 도둑잡기 | `mixed` | 0 · 10 · 50 · 200 |
| 인디언 포커 | `wager` | 10 · 50 · 200 |

## 4. 지급

### 도둑잡기 직접 플레이 순위 보상 (2026-07-26 개정)

```
1등   +10 P
2등    +5 P
3등    +3 P
패배   +1 P
```

직접 플레이를 정상 완료했을 때만 지급하며 선택 베팅 여부와 무관하다. 관전에는 지급하지 않는다.
패배에도 1 P를 지급하므로 신규 사용자의 발행 경로는 끊기지 않는다. 판돈 판의 NPC 지갑은 저장하지 않으므로 시스템 전체를 회계상
`제로섬`이라고 부르지 않는다. 아래 배수 합 0은 **등수표의 대칭성**일 뿐이다.

### 판돈 판 — 대칭 배수표

```
1등   +1.5 × 판돈
2등   +0.5 × 판돈
3등   −0.5 × 판돈
꼴찌  −1.5 × 판돈        합계 0
```

- 판돈 50이면 1등 +75, 꼴찌 −75다.
- 도둑잡기 직접 플레이의 선택 베팅에는 위 순위 보상을 함께 지급한다. 다른 판돈 게임의 참가 보상은 각 게임 계약이 정한다.
- **좌석 수가 4가 아닌 게임은 배수표를 별도로 선언한다.** 등확률 순위에서 기대값이 0이 되도록 배수 합을 0으로 맞춘다.
- 수동 관전 자체에는 보상이 없다. 다만 승자·패자 등을 고르고 판돈을 예약하는 **관전 예측**은 별도 사이드게임이며 정산할 수 있다.

### 예약과 정산

- 판돈 선택 화면에서 **최대 손실 노출액**을 감당할 수 없는 판돈은 고를 수 없다. 위 4인표에서 판돈 50의 예약액은 `50×1.5=75 P`다.
- 시작 시 `wallet + wagerReceipts` 한 트랜잭션에서 최대 손실 노출액을 예약한다. 완료 뒤에만 차감하면 여러 탭·여러 세션이 같은 잔액을 중복으로 약속할 수 있다.
- 일시 이탈·새로고침은 예약을 유지하고 이어하기에서 복구한다. 자발적 `포기`는 해당 게임이 선언한 최악 손실로 정산한다. 불리한 결과를 보고 환불받는 저장 악용을 막는다.
- 캐비닛 버전 불일치·손상처럼 사용자가 통제하지 못한 시스템 폐기만 예약액을 전액 반환한다.
- 완료 시 같은 트랜잭션에서 예약을 해제하고 게임이 선언한 순손익·순위 보상을 반영한다. `(sessionId, settlementSequence)`는 멱등 키다.
- 잔액이 최저 판돈 미만이면 판돈 좌석이 잠기고 무료 좌석만 열린다.

## 6. 이관

**배포된 지갑이 이미 있다.** 잔액을 버리지 않는다.

- `INITIAL_MEDAL_BALANCE = 100`으로 만들어진 기존 잔액은 **그대로 포인트로 이관**한다. 1:1이다.
- 스토어 키와 멱등 기록(`highestSequence`)은 유지한다. 재지급이 발생하면 안 된다.
- 개명은 표기와 식별자에만 적용한다. **이관 중 잔액이 0이 되는 경로를 만들지 않는다.**

## 7. 금지사항

1. **현금 구매·환전·외부 거래 경로를 만들지 않는다.** 포인트는 플레이로만 얻는다.
2. **접속 기반 보상을 만들지 않는다.** 일일 지급·연속 출석·시간 제한 이벤트 금지. 주기가 필요하면 **판수 기반**으로 한다.
3. **포인트를 서버로 보내거나 공유 코드에 담지 않는다.**
4. **실제 금전 가치를 시사하는 표현을 쓰지 않는다.**
5. **초기 자본·파산 구제 로직을 만들지 않는다.** 무료 테이블이 그 역할이다.
6. **판돈 잔액을 `engine.ts`·게임 상태에 넣지 않는다.** 포커처럼 베팅 선택 자체가 규칙인 게임은 베팅 행동을 순수 코어가 소유하되, 지갑 예약·정산은 코어 밖에 둔다.
7. **지갑 잔액이 셔플·카드 배분·표정 진실값에 영향을 주지 않는다.** 포커의 베팅 행동과 판돈 단위는 순수 게임 코어에 기록될 수 있지만, 같은 시드와 정규화된 행동열이면 카드·순위 기록은 같다.
8. **기존 잔액을 초기화하지 않는다.**

## 8. 테스트 관문

1. **개명 이관** — 기존 메달 잔액 100이 포인트 100으로 남는다.
2. **초기 자본 없음** — 새 사용자의 잔액이 0이다.
3. **무료 순위 보상** — 도둑잡기 1·2·3등·패배가 각각 10·5·3·1 P를 받고 관전은 0 P다.
4. **대칭 배수표** — 4좌석 배수 합이 정확히 0이다. 판돈 10·50·200 전부에서.
5. **판돈 상한** — 잔액이 최대 손실 노출액보다 작으면 해당 판돈을 고를 수 없다.
6. **잠금** — 잔액이 최저 판돈 미만이면 판돈 좌석이 잠기고 무료 좌석은 열린다.
7. **멱등** — 같은 `(sessionId, sequence)` 정산이 두 번 반영되지 않는다.
8. **수동 관전 제외** — 예측을 고르지 않은 관전은 잔액을 바꾸지 않는다.
9. **예약 복구** — 최대 손실이 시작 시 예약되고 새로고침 뒤에도 중복 예약 없이 이어지며, 자발적 포기는 최악 손실로 정산된다.
10. **판정 독립** — 같은 시드·정규화 행동열에서 판돈 단위가 달라도 카드 배분·최종 순위 transcript가 같다. 지갑 정산은 게임 `resultHash`의 입력이 아니다.
11. **다중 세션** — 두 탭이 동시에 잔액을 초과해 예약할 수 없다.
12. **시스템 환불** — 버전 불일치·손상으로 진행을 폐기할 때만 예약액이 정확히 전액 반환된다.

E2E

13. 잔액 0에서 무료 도둑잡기를 완주하면 실제 순위에 맞는 10·5·3·1 P가 생긴다.
14. 그 포인트로 판돈 판을 열 수 있다.
15. 새로고침 후 이어하기로 돌아오면 예약 노출액과 사용 가능 잔액이 정확히 복구된다.

## 9. 완료 조건

- `pnpm boundaries`·`pnpm typecheck`·`pnpm test`·빌드 통과.
- 8절 관문 15개 통과.
- 사용자 UI와 현행 계약에 폐기된 `메달` 표기가 남지 않는다. 이관 기록·대체된 역사 문서는 예외다.
- 기존 사용자의 잔액이 보존된다.
