# SPEC-A30 — 살아 있는 카지노 플로어

> 상태: 구현 계약 (2026-07-27). [SPEC-A26](./SPEC-A26-living-casino-npc-ledger.md)의 원장을
> 화면과 게임 선택에 연결하고, 원장 정산 계약을 `npc-ledger/0.2`로 승격한다.

## 1. 목적

카지노 플로어는 정지한 순위표가 아니다. NPC 35명의 활동을 UTC 시각에서 결정론적으로 복원해
테이블 입장·게임 중·정산·퇴장 상태를 보여 준다. 같은 시각을 보는 클라이언트는 같은 NPC의
자리와 잔고를 계산하며 서버 프로세스나 NPC 전용 저장소는 사용하지 않는다.

## 2. 원장 0.2 정산

`npc-ledger/0.1`의 임의 OU 변동을 폐기한다. 각 세션은 공개 게임의 정산 단위만 사용한다.

- 도둑잡기: 무료 입장, 순위 보상 `10 / 5 / 3 / 1 P`
- 짝맞추기: `10 / 50 / 200 P` 판돈과 `0 / 1 / 1.5 / 2 / 2.5배` 환급
- 인디언 포커: 같은 판돈, 획득 칩 수에 따른 환급
- 슬롯 777: 같은 판돈, 적중 라인 수와 공개 배당표에 따른 환급

모든 세션은 `reservedAmount`, `creditAmount`, `delta`, `resultKind`, `termsVersion`을 남기며
항상 `delta === creditAmount - reservedAmount`다. NPC 목표 잔고·변동성·평균회귀 값은 결과 후보의
확률만 조정한다. 정산표에 없는 금액을 결과에 맞추기 위해 만들어 내지 않는다.

0.1은 개점 당일의 표시 실험이었으므로 0.2는 같은 기준일에서 즉시 재기준한다. 0.1 캐시는
진실이 아니며 0.2 키로 다시 계산한다. 사용자 지갑·기존 게임 저장·결과 해시는 이 승격과 무관하다.

## 3. NPC 현장 상태

세션마다 테이블별 길이 범위 안에서 결정론적 체류 구간을 만든다.

`입장 중 → 게임 중 → 정산 중 → 퇴장 중 → 대기`

- 슬롯 2~4분, 인디언 포커 4~7분, 짝맞추기 5~9분, 도둑잡기 6~10분
- 현재 세션의 결과는 정산 시각 전까지 화면에 공개하지 않는다.
- 어느 전이 시각에도 최소 4명은 초대 가능한 상태여야 한다.
- 기기 시각이 아니라 콘텐츠 매니페스트 응답의 HTTP `Date`로 보정한 UTC 초를 쓴다.

## 4. 플로어 표현

- 명예의 전당 잔고는 분 단위로 바뀌며 변경 행을 짧게 강조한다.
- 최근 활동은 실제 0.2 정산액과 판돈을 표시한다.
- 공개 게임 네 개는 고정 카드 대신 살아 있는 테이블 카드로 렌더한다.
- 카드에는 게임 중인 NPC, 남은 시간, 최근 정산과 가벼운 게임별 미니 루프를 표시한다.
- 미니 루프는 장식이며 게임 리플레이를 사칭하지 않는다. 감소 모션에서는 정지한다.

## 5. 게임 초대 잠금

도둑잡기·짝맞추기·인디언 포커의 상대 선택기는 현재 다른 테이블에 있는 NPC를 잠근다.

- 잠긴 인물은 현재 테이블과 복귀 예정 시간을 표시한다.
- 무작위 선택은 초대 가능한 인물만 사용한다.
- 선택한 인물은 현재 탭에서 2분 동안 임시 초대 상태로 잡는다.
- 임시 초대는 `sessionStorage` 표현 계약이며 공개 원장이나 다른 사용자에게 영향을 주지 않는다.
- 이미 시작했거나 복구하는 대국은 뒤늦은 원장 변화로 폐기하지 않는다.
- 서버 없는 구조이므로 전 세계 사용자 사이의 좌석 독점은 보장하지 않는다.

## 6. 비범위

NPC 대국의 프레임별 실제 리플레이, 서버 동기화, 계정, 세계 공용 좌석 예약, 라이브 오즈 시장은
포함하지 않는다. 플로어의 NPC 활동은 공개 게임 정산표를 사용한 결정론적 스핀오프 원장이다.

## 7. 완료 관문

1. 35명 × 10,000일 계산이 결정론적이고 잔고가 `[0, 20μ]` 안에 남는다.
2. 모든 세션의 `delta`가 예약·환급 금액과 정확히 일치한다.
3. 현장 상태 전이마다 최소 4명의 초대 가능 NPC가 남는다.
4. 세 게임의 직접 선택·무작위 선택·시작 직전 검사가 바쁜 NPC를 거부한다.
5. 원장을 제거해도 모든 게임의 동일 시드 `resultHash`가 같다.
6. `pnpm check`, 전체 E2E, 초기 JS gzip 200 KiB 예산을 통과한다.
