# SPEC-A32 — 짝맞추기 기억 지능·NPC 관전

> 상태: 구현 완료 · 검증 및 대사 문안 대기 (2026-07-28).
> 선행: [SPEC-A27](./SPEC-A27-match-pairs-versus.md).

## 1. 발견한 문제

- CPU는 숨은 카드 배열을 받지 않았지만 공개된 모든 카드를 `confidence: 1`로 관찰했다.
- 쉬움 12장 보드에서 최상위 기억 용량이 10장이어서 사실상 전체 판을 기억했다.
- 30명이 도둑잡기 성격 두 축을 거쳐 7개 숫자 조합으로 압축됐고, 15명이 동일한 최상위형이었다.
- 명세가 말한 탐색 성향은 실제 선택기에 연결되지 않았다.
- 짝을 맞히면 차례가 유지되므로, 완성된 짝 여러 개를 기억한 CPU가 후반을 연속으로 정리했다.

대표 지능형 7개를 무작위 초보 플레이어와 각 1,000판 실행했을 때 쉬움 NPC 승률은 70.6~94.7%,
최상위형의 3연속 이상 성공 비율은 86.1%였다. 실제 사용자 승률이 아니라 과도한 기억 압력을 확인한
진단 기준이다.

## 2. 동결된 짝맞추기 전용 인격

`temerosa-match-pairs-personas.ts`에 30인 리터럴을 둔다. 다른 캐비닛의 성격을 런타임 변환하지 않는다.

- `memoryCapacity`: 동시에 유지하는 위치 수, 3~7
- `observationRate`: 상대가 공개한 카드를 실제로 주시하는 비율
- `recallAccuracy`: 저장한 위치를 꺼내는 정확도
- `memoryRetention`: 시도 뒤 기억 유지
- `consistency`: 같은 기억 안에서 우선순위를 지키는 정도
- `searchStyle`: `explore | recheck | mixed`
- `streakComposure`: 연속 성공 중 집중 유지
- `difficultyTier`: 1~3. UI에는 별만 표시하며 정본상 지능이라고 주장하지 않는다

이 값은 카지노 게임용 해석이며 캐릭터의 정본 IQ가 아니다. 배포 뒤 조정하려면 계약과 세션을 올린다.

### 2.1 NPC 기억 집중도

직접 대결에는 캐릭터 교체와 별도로 `느긋함 | 보통 | 날카로움`을 둔다. 캐릭터별 프로필은 그대로 두고,
선택한 집중도가 기억 용량·관찰·회상·보존에 작은 공통 보정을 적용한다. 따라서 같은 집중도에서도
알제와 율은 서로 다른 방식으로 플레이한다.

- `느긋함`: 기본값. 기억 압력을 낮추고 승리 환급률도 0.25 낮춘다.
- `보통`: 동결된 인물별 프로필과 환급률을 그대로 쓴다.
- `날카로움`: 기억 압력을 높이고 승리 환급률도 0.25 높인다.

집중도는 상태·WAL·판돈 영수증의 선택 키에 포함한다. 재접속했을 때 같은 시드와 같은 집중도로 복구해야 한다.
레버리지 배율은 별도 경제 축이며 최대 손실과 반환에 대칭으로 적용한다.

## 3. 정보 경계

선택 함수는 계속 `MatchPairsNpcRead`만 받으며 `cards`를 받지 않는다. 공개 순간 각 CPU는 독립된 결정론
관찰 판정을 거친다. 카드를 직접 연 CPU는 자기 카드를 반드시 보지만 상대 CPU는 놓칠 수 있다.
관찰·회상·탐색 난수는 좌석과 사건이 포함된 별도 시드 영역을 쓴다.

정답 뒤 연속 차례는 원래 규칙이므로 몰래 횟수를 제한하지 않는다. 관찰 누락, 기억 용량, 연속 집중으로
체감을 조정한다.

## 4. NPC 대 NPC

내부 좌석 id는 기존 WAL 호환 어휘인 `player | npc`를 유지하되, `mode: spectate`에서는 둘 다 CPU다.

- `opponentIds.player`와 `opponentIds.npc`에 서로 다른 NPC가 앉는다.
- `npcMemories`, `reactions`, `matchStreaks`는 좌석별로 완전히 분리한다.
- 두 NPC 직접 선택 또는 결정론적 무작위 대진이 가능하다.
- 양쪽이 같은 공개 정보만 받고 숨은 카드 배열은 받지 않는다.
- 승자 예측은 기존 `spectator-prediction/0.3`의 `first-place` 시장을 재사용한다.
- 무승부는 시스템 환불한다.
- 관전 기록은 `outcome: spectated`로 남겨 플레이어 대전 전적에 섞지 않는다.

## 5. 대사 배선

사건 12개와 순수 선택기는 구현했다. 런타임 배열은 제미나이 검수 전까지 빈 배열이다.

`table-open · self-match · self-miss · opponent-match · opponent-miss · streak · ahead · behind · last-pair · victory · defeat · draw`

검수 워크시트는 [TEMEROSA-MATCH-PAIRS-DIALOGUE.md](./TEMEROSA-MATCH-PAIRS-DIALOGUE.md)다.
30명 × 12상황 360줄이 확정되면 문서에서 런타임 파일을 생성하고 글자 단위 대조 테스트를 붙인다.
대사는 판정·WAL·resultHash에 들어가지 않으며 복구 재생 중 발화하지 않는다.

## 6. 계약과 저장

- 코어 `match-pairs/0.4`
- 상태 `match-pairs-state/0.4`
- 카트리지 `temerosa-match-pairs/0.3`
- 세션 `temerosa-match-pairs:versus-2`
- 판돈 조건 `match-pairs-paytable/0.3`

기존 0.3 진행 상태는 새 CPU 결정과 섞지 않는다.

## 7. 다음 검증 관문

6. 직접 대전 지갑과 관전 예측 지갑의 예약·복구·정산·무승부 환불

8. 제미나이 확정 360줄과 런타임의 글자 단위 대조
