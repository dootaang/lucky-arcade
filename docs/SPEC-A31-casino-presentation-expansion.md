## 0. 한 줄

**시간 축이 극단적으로 기울어 있다. 99.5%인 `playing`이 아니라 26초짜리 희소 사건에 빛을 몰아준다.**

## 1. 이 명세가 다시 쓰인 이유

같은 날 오전 초안 이후 `bd3b8ef` · `c626bd5` · `a105ddc` 세 커밋으로 전제가 움직였다.

### 1.1 이미 구현되어 이 명세에서 빠진 것

| 초안 항목 | 현재 상태 |
|---|---|
| 라이브 테이프 플래시 | **완료.** `ledger-enter`(진입 시 `brightness(1.8)`) + `ledger-settle-flash .85s` + 상승/하락 색 |
| 정산 강조 | **완료.** `.ledger-settlement-line` 3영역 레이아웃 · `NumberTicker` · `text-shadow` · `is-fresh` 도착 연출 |
| 명예의 전당 플래시 | **부분 완료.** `ledger-balance-flash`가 붙었으나 6절의 재시작 결함이 남았다 |

### 1.2 전제가 바뀐 것

```
NpcActivity (분 해상도)      →  NpcRoundSettlement (초 해상도, roundId 보유)
정산 = 방문당 1회             →  방문 안에서 세부 판이 계속 정산 (npc-live-rounds/0.1)
방문 길이 2~10분              →  45~120분  (presence.ts DURATION_SECONDS)
잔고 = 분 단위 스냅숏          →  npcLiveBalancesAt 로 초 단위 라이브
```

### 1.3 새로 쓸 수 있게 된 데이터

`NpcPresence`가 `openingBalance` · `startedAtUtcSecond` · `settlesAtUtcSecond`를 갖게 됐다.
**방문 진행률과 방문 중 손익을 추가 계산 없이 뺄셈으로 얻는다.** 4절이 여기서 나온다.

`NpcRoundSettlement.resultKind`도 구체값이 됐다 — `lines-1` · `win-2x` · `chips-20` · `rank-2` · `rank-last`.

## 2. 지금의 진짜 문제 — 시간 축 불균형

`presence.ts`의 실측값이다.

```
approaching   12초        ┐
playing       45~120분    │  전이 3종을 합쳐 26초
settling       6초        │  playing이 전체의 99.5%
leaving        8초        ┘
```

여기서 두 가지가 따라 나온다.

**① `playing`에는 시각 예산을 거의 쓰지 않는다.** 상시 상태에 연출을 걸면 그건 연출이 아니라 배경이고,
45분 내내 도는 애니메이션은 비용만 낸다.

**② 26초짜리 전이가 이 화면에서 유일하게 희소한 사건이다.** 놓치면 다음 기회까지 수십 분이다.
디자인 자산에서 뽑은 1회성 연출(`.ca-scan` 통과, `.ca-glare` 번쩍)이 정확히 이 자리에 맞는다.

**③ 남은 시간 텍스트는 정보가 아니다.** `remainingLabel`이 `"게임 중 · 48분 12초 남음"`을 매초 갱신하는데,
45~120분 방문에서 이 숫자는 아무 결정도 바꾸지 않는다. 초 단위 갱신은 **비용만 내고 눈만 흔든다.**

> 방문이 2~10분이던 시절의 표시다. 7절에서 이 자리를 다른 정보로 바꾼다.

## 3. 프레즌스 표현 계약

`LiveTableCard`는 이미 `live-player is-${phase}` 클래스를 DOM에 내보내고 있으나 **CSS가 0줄이다.**
훅이 이미 있으므로 스타일만 붙이면 된다.

| 상태 | 지속 | 부품 | 읽히는 뜻 |
|---|---|---|---|
| 빈 테이블 | — | `.ca-shine` 상시 회전 | **들어와도 된다** |
| `approaching` | 12초 | `.ca-scan` **1회** 통과 | 누가 들어오고 있다 |
| `playing` | 45~120분 | `.ca-brackets`만 | 자리 있음 — 조준선만. **애니메이션 없음** |
| `settling` | 6초 | `.ca-glare` 1회 + 금액 착지 | 결과가 나오는 순간 |
| `leaving` | 8초 | `.ca-reflect` + 불투명도 감쇠 | 빠져나간다 |

### 규칙

- `.ca-shine`은 **빈 테이블에만**. 전부에 두르면 "어디가 비었나"라는 정보가 사라진다.
- kit의 `.ca-scan`은 `infinite`다. 이 자리에서는 `animation-iteration-count: 1`을 상태 클래스에서
  덮는다. **kit 원본은 고치지 않는다.**
- `.ca-holo`는 `::before`/`::after`를 모두 소유하므로 `.ca-shine`·`.ca-glare`와 같은 요소에 겹치지 않는다.
- `playing`에 애니메이션을 걸지 않는다. 2절 ①.

## 4. 방문 진행률과 방문 손익 ★ 새 데이터로만 가능

45~120분 방문을 볼 만하게 만드는 유일한 축이다. **패널은 이미 `presences`와 라이브 `npcBalances`를
둘 다 받고 있으므로 새 계산이 없다. 뺄셈 두 번이다.**

```ts
진행률 = (now - startedAtUtcSecond) / (settlesAtUtcSecond - startedAtUtcSecond)
방문손익 = npcBalances[npcId] - presence.openingBalance      // npcLiveBalancesAt 결과를 씀
```

### 4.1 방문 손익을 초상에 붙인다

`live-player` 초상 테두리를 `--ca-rising` / `--ca-falling`로 물들인다. 색만 쓰고 숫자는 쓰지 않는다.

**이것이 "저 사람 지금 따고 있다"를 만든다.** 지금 화면은 누가 앉아 있는지만 알려 주고 어떻게
하고 있는지는 정산 목록을 따로 읽어야 안다. 45분 방문에서 이건 큰 차이다.

- 손익 0이면 물들이지 않는다. 중립을 색으로 표현하면 색이 의미를 잃는다.
- 세부 판이 정산될 때만 값이 바뀌므로 갱신이 잦지 않다. 매초 깜빡이지 않는다.

### 4.2 진행률은 막대가 아니라 테두리 게이지로

`live-table-card` 테두리 하단을 `scaleX`로 채운다. 별도 요소를 만들지 않는다.

- `transform: scaleX(var(--progress))` · `transform-origin: left`. **`width`를 쓰지 않는다.**
- 45~120분 구간이라 **transition을 걸지 않는다.** 매초 1/2700씩 늘어나는 값에 160ms 보간은 무의미하다.
- 진행률은 `playing`에만 표시한다. 전이 상태에서는 감춘다.

## 5. 명예의 전당 — 깊이 막대

Stitch 베팅 터미널(`stitch_dark_fantasy_betting_terminal/`)의 행 구조를 적용한다.
[SPEC-A29 12절](./SPEC-A29-live-odds-market-panel.md)의 색·형태 규칙을 그대로 상속한다.

```css
.casino-ledger-board tr::before {
  transform: scaleX(var(--depth));                              /* 0 ~ 1 */
  transform-origin: left;
  transition: transform 160ms cubic-bezier(.34, 1.2, .64, 1);   /* 1.2 오버슛 = 탄력 */
  border-radius: 0;                                             /* 둥글리면 진행바로 보인다 */
}
```

- `--depth`는 **표시 중인 최고 잔고를 1.0으로 정규화**한다. 절대 상한을 만들지 않는다.
- 막대는 `--ca-rising` / `--ca-falling` 15% 불투명도, 텍스트는 100%.
- `npcLiveBalancesAt` 덕분에 잔고가 이제 초 단위로 움직인다. **초판을 쓸 때보다 막대가 더 값지다.**
- 기존 `ledger-balance-flash`와 함께 쓴다. 막대는 크기, 플래시는 변화다.

> 라이브 오즈 시장 패널(A29)은 여전히 보류다. 이 절은 명예의 전당에만 적용하며, 같은 시각 어휘를
> 이미 있는 데이터로 먼저 검증하는 리허설이다.

## 6. 명예의 전당 플래시 재시작 — 남은 유일한 플래시 결함

테이프 행은 `key={event.id}`로 **매번 새로 마운트**되므로 진입 애니메이션이 자연히 재생된다.
그러나 명예의 전당 `<tr>`은 `key`가 NPC id라 **재사용된다.** `is-changing is-rising` 클래스가
붙은 채로 같은 방향 변화가 또 오면 애니메이션이 재시작되지 않는다.

```ts
row.classList.remove("is-changing");
void row.offsetWidth;                 // 리플로우 강제
row.classList.add("is-changing");
```

세부 판 정산이 초 단위로 흐르는 지금 구조에서는 **같은 NPC가 1.6초 안에 두 번 바뀌는 일이 실제로 생긴다.**

## 7. 남은 시간 자리를 초대 가능 인원으로

2절 ③에 대한 답이다. `"게임 중 · 48분 12초 남음"`을 다음으로 바꾼다.

```
게임 중 · 3명            ← 이 테이블에 앉아 있는 수
지금 초대 가능 · 6명      ← presences 중 phase === "idle" 인 수 (플로어 헤더)
```

- A30 §5는 "어느 전이 시각에도 최소 4명은 초대 가능"을 보장한다. 그 보장이 화면에 보이지 않는다.
- 45~120분 잠금이면 사용자가 **부르고 싶은 인물을 대부분 못 부른다.** 몇 명이 가능한지가 남은 시간보다
  훨씬 중요한 정보다.
- 정확한 복귀 시각은 상대 선택기에서 **그 인물을 눌렀을 때만** 보여 준다. 카드 표면에 두지 않는다.
- 초 단위 텍스트 갱신이 사라지므로 매초 리렌더의 DOM 쓰기도 줄어든다.

## 8. 슬롯 — 두 곳

램프 오프셋 · 릴 정지 캐비닛 충격 · 당첨선 스태거 draw · 컷인 · 스윕은 이미 있다. 둘만 더한다.

### 8.1 램프를 백열전구로

```css
/* 현재 */ box-shadow: 0 0 10px #ffd777;                     /* 평면 점 + 단일 글로우 */
/* 계약 */ box-shadow: 0 0 1px inset, 0 0 2px inset, 0 0 10px inset,
                       0 0 40px, 0 0 100px, 0 0 5px;         /* inset 3중 + 외곽 3중 */
```

동시에 딜레이 주기를 소수로 바꾼다. 현재 `3n+2` · `3n`은 램프 9개를 3개 그룹으로 뭉쳐 보이게 한다.
`7n` · `11n` · `13n`은 9와 서로소라 마퀴가 실제로 흐른다.

### 8.2 리치 — 계단식 감속

```css
@keyframes …  { 0% {…}   12.5%, 25% {…}   37.5%, 50% {…}   62.5%, 75% {…} }
```

키프레임 두 개를 같은 값으로 두어 **정지 구간**을 만든다 — 돌다가 멈추고, 또 돌다가 멈춘다.

`slot-reach` 이벤트 코드는 `live-tape.ts`의 `ACTIONS["temerosa-slot"]`에 들어 있어 **실제로 테이프에
흐르고 있다.** 그런데 슬롯 화면의 릴은 등속 감속이라 리치가 원장에만 있고 눈에는 없다.
마지막 릴에만 적용하며 릴 정지 순서·당첨 라인·`resultHash`는 바뀌지 않는다.

## 9. 인물 층

### 9.1 Backlight — 인물 색이 곧 조명색

초상의 blur 복제본을 뒤에 깐다. 35명이 각기 다른 색이라 **추가 자산 0으로 자리마다 다른 조명**이 나온다.

블러 예산(11절) 때문에 플로어에서는 **`settling` 중인 1명에게만** 건다. 6초짜리 희소 사건이므로
상시 비용이 없고, 2절 ②와 정확히 맞는다.

### 9.2 HoverEffect — 상대 선택기

색 블록이 hover한 칸 뒤로 미끄러진다. motion의 `layoutId` 없이 절대위치 요소 1개 + `transform`
transition으로 근사한다. **데스크톱 hover 한정**, 터치 기기는 기존 표시를 유지한다.

7절 때문에 선택기의 잠금 표시가 중요해졌으므로 이 절의 우선순위가 초판보다 올라간다.

### 9.3 EvervaultCard — 바쁨과 모름을 구분한다

```
바쁨(잠김)    흐림 + 복귀 시각          정보가 있다
모름(미대면)  난수 문자 벽              정보가 없다
```

선행 조건: "이 인물과 대국한 적 있음"을 남기는 로컬 저장이 필요하다. **없으면 착수하지 않는다.**

### 9.4 PixelImage — 카지노 플로어에서는 철회

초판은 "정산 시각 전까지 결과 비공개"(A30 §3)를 픽셀이 걷히는 연출로 쓰자고 했다. **철회한다.**

`npc-live-rounds/0.1`이 세부 판을 초 단위로 이미 공개하고, 방문 최종 판도 `settlesAtUtcSecond - 1`에
테이프로 흐른다. **가릴 것이 남아 있지 않다.** 없는 비밀에 여는 연출을 붙이면 거짓말이 된다.

PixelImage는 원래 자리인 **도감 해금(12 P)과 짝맞추기 카드 공개**로 되돌린다. 이 명세의 범위 밖이다.

## 10. 데이터에 반응하는 배경

셋 다 **이미 계산된 값**을 표현에 흘린다. 새 계산이 없다.

| 항목 | 입력 | 표현 |
|---|---|---|
| 금가루 속도 | `lastMinuteCount` (패널이 이미 계산) | `.ca-tableau` drift 주기를 `calc(150s - var(--ca-busy) * 1.5s)`로. **바쁘면 공기가 빨리 흐른다** |
| 스포트라이트 기울기 | 최근 정산 `delta` 합의 부호 | `.ca-spotlight`의 금/진홍 두 줄기 세기를 기울인다. 카지노 전체의 기분 |
| 1위 포일 | 명예의 전당 1위 | `HoloFoil` 1장. **동시 1장 제한을 지키면서 왕관이 된다** |
| 미니 루프 맥박 | `NpcPlayEvent` 도착 | 루프가 **한 번 튄다**. 동작을 흉내내지 않는다 |

> **미니 루프 경계선**: A30 §4가 "미니 루프는 장식이며 게임 리플레이를 사칭하지 않는다"고 했다.
> 이벤트 종류에 따라 동작을 바꾸면 사칭에 가까워진다. **맥박(한 번 튐)까지만 허용한다.**

### 매초 재계산이라는 선행 제약

`CasinoLedgerView`는 1초 타이머로 리렌더하고, 그 렌더 본문에서 `recentNpcRoundSettlementsAt`(35 프로필 ×
최대 3일 × 방문마다 `npcVisitRounds` 전개)과 `npcLiveBalancesAt`를 다시 돌린다.

**새 애니메이션을 얹기 전에 이 메인스레드 작업이 프레임을 먹는지 먼저 측정한다.** 합성만 하는 CSS
애니메이션은 영향이 작지만, 매초 DOM 쓰기가 늘어나는 변경(7절 이전의 초 단위 텍스트 등)은 같이 줄인다.
이 명세는 그 부하를 **늘리지 않는 방향**으로만 설계되어 있다 — 7절이 오히려 줄인다.

### 네임스페이스 정리

`.ca-idle`이 kit이 아니라 `cabinets/casino-ledger/src/react/casino-ledger-panel.css`에 있다.
`casino.css` 파일 주석이 `.ca-*`를 kit 네임스페이스로 선언했으므로 **kit으로 옮긴다.**

### 문서 불일치 하나

A30 §3은 방문 길이를 `슬롯 2~4분 · 인디언 포커 4~7분 · 짝맞추기 5~9분 · 도둑잡기 6~10분`으로 적었으나,
현재 `presence.ts`와 A26 §15(2026-07-27 오너 승인)는 **45~120분**이다. **A26 §15가 최신이다.**
A30 §3을 갱신하거나 A26을 참조하도록 고친다.

## 13. 비범위

- 라이브 오즈 시장 패널 (A29는 여전히 보류)
- 새 게임·새 테이블·새 정산 규칙·라운드 구성 변경
- 도감 해금 연출 (9.4에서 PixelImage를 이쪽으로 되돌렸으나 별도 작업이다)
- 오디오. `.ca-*` 어느 부품도 소리를 전제하지 않는다
- 자이로. 터치 기기는 `data-holo-drift`를 계속 쓴다
- 서버 동기화·계정·NPC 실제 리플레이
- 새 외부 의존. `canvas-confetti` 외에 추가하지 않는다

## 14. 완료 관문

1. 프레즌스 5상태가 각각 **구분 가능한 시각 처리**를 받고, `playing`에는 상시 애니메이션이 없다.
2. `.ca-shine` · `.ca-scan` · `.ca-reflect` · `.ca-pulse` · `.ca-gold-rim` 중 **미배선 부품이 0개**다.
3. 방문 중 손익이 0이 아닌 NPC 초상만 상승/하락 색을 받고, 손익 0은 물들지 않는다.
4. 테이블 카드가 초 단위로 갱신되는 잔여 시간 텍스트를 더 이상 표시하지 않고, 초대 가능 인원을 표시한다.
5. 깊이 막대가 `scaleX`로만 움직이고 35행에서 레이아웃 재계산이 발생하지 않는다.
6. 같은 NPC의 잔고가 1.6초 안에 같은 방향으로 두 번 바뀌어도 명예의 전당 플래시가 **두 번** 재생된다.
7. 어느 화면에서도 블러 생성 레이어가 3개를 넘지 않고 포일이 동시에 2장 이상 뜨지 않는다.
8. `prefers-reduced-motion`에서 이 명세가 추가한 모든 애니메이션이 정지한다.
9. 슬롯 릴 정지 순서·당첨 라인·`resultHash`가 8절 적용 전후로 동일하다.
10. 원장·프레즌스·라운드 계약(A26 §15·§16, A30)의 어떤 값도 이 명세로 바뀌지 않는다.
11. `pnpm check`, 전체 E2E 통과. 초기 JS gzip **145 KiB 이하** 유지(현재 137.3).
12. 데스크톱·모바일 스크린샷으로 플로어·테이블·슬롯 세 화면을 육안 확인한다.
