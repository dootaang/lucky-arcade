# SPEC-A33 — 카지노 기록실과 NPC 하이로우 원장

> 상태: 구현 계약 (2026-07-29). 선행: NPC 원장 0.7, 공개 하이로우 0.3.

## 1. 목적

플로어의 `명예의 전당`은 상위 5명과 플레이어만 보여 주는 요약판으로 남긴다. `전체 보기`를 누르면
NPC 35명과 플레이어의 전체 순위를 열고, NPC 행을 누르면 그 NPC가 어느 게임에서 포인트를 얻고
잃었는지 확인할 수 있는 `카지노 기록실`을 연다.

동시에 공개된 하이로우를 NPC 원장에도 편입한다. 지금까지 하이로우는 플레이어만 이용하는 공개
테이블이었고 NPC 원장의 `CasinoTableId`와 일일 일정에는 포함되지 않았다.

## 2. 정보 구조

### 2.1 전체 순위

- NPC 35명과 플레이어 1명을 실제 순위대로 모두 표시한다.
- `7일 손익`과 `잔고` 정렬을 유지한다.
- 동률이면 NPC는 id 사전순, 플레이어는 같은 잔고의 NPC 뒤에 둔다.
- 플로어 요약판은 상위 5명과 플레이어 고정 행을 계속 사용한다.
- NPC 행은 버튼/링크로 동작하며 개인 원장을 연다. 플레이어 행은 이번 범위에서 상세를 열지 않는다.

### 2.2 NPC 개인 원장

`전적`과 `정산`을 섞지 않는다. 슬롯과 하이로우는 대전 승패보다 손익이 중요한 게임이므로 개인 화면은
다음 두 축을 함께 보여 준다.

- 요약: 현재 순위·현재 잔고·누적 순손익·수익/손실/무변동 정산 수·최대 수익·최대 손실.
- 게임별 손익: 정산 수·총 노출액·총 지급액·순손익.
- 잔고 흐름: 계약 기준일 이후 정산의 누적 손익을 작은 선 그래프로 표시한다.
- 전체 정산 기록: 시각·게임·상대·판돈·배율·결과·순손익을 최신순으로 표시한다.
- 기간 필터는 `24시간 / 7일 / 30일 / 전체`, 게임 필터는 `전체 / 게임별`로 둔다.

원장에 없는 카드 배열·선택·판단 과정을 발명하지 않는다. `전체 정산 기록`은 재생 영상이 아니라 실제
`NpcSession` 영수증의 설명이다.

## 3. 계산과 성능

- 전체 순위 계산은 순수 함수다.
- NPC 개인 원장은 사용자가 NPC를 눌렀을 때 그 한 명만 지연 계산한다.
- 정본은 `(contract, npcId, UTC second)`의 순수 계산이며 캐시는 선택 사항이다.
- 플로어의 매초 갱신 때문에 30일 기록을 매초 다시 만들지 않는다. 상세를 열거나 기간을 바꿀 때만 계산한다.
- 기록은 한 번에 최신 50건을 표시하고 `더 보기`로 늘린다.

## 4. 하이로우 NPC 계약 0.8

### 4.1 재기준

하이로우를 테이블 집합에 넣으면 일정과 이후 모든 난수열이 달라지므로 `npc-ledger/0.8`로 올린다.
기준일은 2026-07-29 00:00 UTC다. 0.8의 시작 잔고는 0.7이 2026-07-28 하루를 마친 종가를 전사해
연속성을 보존한다. 과거 0.7 체크포인트는 읽지 않는다.

### 4.2 실제 플레이어와 같은 경제

- 판돈은 10/50/200 P, 외부 배율은 2/3/4/5배다.
- 내부 하이로우 반환 배율은 공개판 0.3과 같은 `1.3 / 1.9 / 2.7 / 4 / 5.5`다.
- 같은 숫자는 실패다.
- 예약액은 `판돈 × 외부 배율`, 지급액은 `round(판돈 × 내부 반환 배율) × 외부 배율`이다.
- 실패하면 예약액 전부를 잃는다. NPC만 쓰는 완화 배당을 만들지 않는다.

### 4.3 판단

- 카드 숫자는 2~A(14)에서 결정론적으로 뽑는다.
- `highLowJudgment`는 더 유리한 방향을 고르는 정확도다.
- `riskAppetite`와 `winPressing`은 적중 뒤 계속 도전할 확률을 높인다.
- `discipline`은 불리한 확률과 이미 확보한 배당 앞에서 멈출 확률을 높인다.
- `lossChasing`은 당일 손실 뒤 판돈·배율 선택에만 관여하며 카드 정답을 알려 주지 않는다.
- 모든 결정과 카드열은 결과 시드에서 파생하고 화면·원장 조회 여부에 영향받지 않는다.

워어즈는 플레이어 하이로우의 하우스 딜러다. NPC 원장 하이로우에서도 하우스는 잔고를 가진 36번째
참가자가 아니며, 플레이 NPC 한 명의 정산만 기록한다.

## 5. 표시

- 하이로우 활동은 플로어 좌석·최근 정산·LIVE PLAY TAPE에 나타난다.
- 플레이 테이프 사건은 `예측`, `연속 적중`, `수익 확정`으로 제한한다.
- 개인 원장에는 `N연속 확정`, `N번째 예측 실패`를 표시한다.
- NPC가 하이로우 중이면 다른 공개 대전의 상대 선택에서 일시적으로 사용할 수 없다.

## 6. 검증 관문

1. 전체 순위에는 NPC 35명과 플레이어가 각각 한 번만 나온다.
2. 요약판은 상위 5명과 플레이어 고정 행을 유지한다.
3. NPC 상세의 게임별 손익 합과 전체 정산 합이 정확히 일치한다.
4. 기간·게임 필터가 원장 영수증을 누락하거나 중복하지 않는다.
5. 같은 계약·시각·NPC는 같은 상세 기록을 만든다.
6. 하이로우 승패는 공개판 0.3 배당과 같은 수식으로 정산된다.
7. 365일 감사에서 하이로우 적중·실패·중도 확정이 모두 발생한다.
8. NPC 잔고는 음수가 되지 않고 안전 정수 범위를 지킨다.
9. 기록실을 열지 않아도 기존 게임 resultHash는 변하지 않는다.
10. 초기 JS gzip 200 KiB 예산과 접근성 관문을 통과한다.
