# SPEC-A16 — Venue 계층과 테메로세 카지노

> 상태: v1.0 구현 계약 (2026-07-25). 선행: [SPEC-A13](./SPEC-A13-point-economy.md).
> [SPEC-A15](./SPEC-A15-lobby-hero-art.md)의 공개 로비 아트 범위를 흡수한다.

## 1. 제품 구조

럭키★오락실은 중립 플랫폼으로 남는다. 현재 공개 Venue는 하나지만 배열과 레지스트리는 여러 Venue를 전제로 한다.

```text
럭키★오락실 로비
└─ 테메로세 카지노
   └─ 여백의 카지노 플로어
      ├─ 무료 도둑잡기
      ├─ 인디언 포커
      ├─ 관전석
      ├─ 슬롯·빙고 등 기계 구역
      ├─ 더비 중계
      └─ 교환소
```

소녀전선, 개인 카드 삽입, 다른 비공개 캐비닛은 UI에서 숨긴다. 코드·저장·유닛 테스트는 보존한다.
GFL 에셋을 저장소와 배포물에서 제거하는 일은 별도 결정이다.

## 2. 정본 경계

`여백의 카지노`, 워어즈의 하우스 배역, 알제의 규정·교환소 배역은 **[게임 연결부]**다. 여백이 여러 시대의
기억과 항로에 닿는다는 정본을 UI 무대로 확장하지만, 원작에 카지노가 있었다고 주장하지 않는다.

- 배역은 기존 성격·화법의 표현이며 새 과거·관계·권한을 발명하지 않는다.
- 카지노 대사는 기존 대사집을 무맥락 재사용하지 않는다. 사건 의미가 같은 줄만 쓰거나 별도 검수를 거친다.
- 시대가 다른 외형은 자동 혼합하지 않는다. 테이블별 승인된 `appearanceSet`을 선언한다.

## 3. 선언 계약

```ts
interface VenueManifest {
  id: string;
  title: string;
  tagline: string;
  heroImage: ResponsiveImageRef;
  entryLabel: string;
  order: number;
  cabinetIds: readonly string[];
}
```

- `PUBLIC_VENUE_IDS = new Set(["temerosa-casino"])`가 로비 노출을 정한다.
- 공개 캐비닛 허용 집합은 공개 Venue의 `cabinetIds` 합집합에서 파생한다. `PUBLIC_CABINET_IDS`를 별도로 중복 관리하지 않는다.
- 캐비닛은 한 Venue에만 속한다. 교차 Venue 게임이 필요해질 때 별도 링크 개념을 설계한다.
- `world` 표시 문자열은 Venue 제목에서 파생하며 캐비닛마다 반복 저장하지 않는다.
- 개발용 비공개 경로는 `import.meta.env.DEV`에서만 열리고 프로덕션 쿼리로 우회할 수 없다.

## 4. 화면과 이동

홈은 `이어하기 → Venue 목록`만 핵심 동선으로 그린다. 현재 `내 카드로 놀기`와 공개 미니게임 목록은 숨긴다.

- Venue 카드는 승인된 16:9 파생본을 가득 채우고 제목·태그라인·입장 버튼을 표시한다.
- Venue에 들어가면 카지노 플로어가 테이블을 `무료`, `빠른 테이블`, `심리 테이블`, `관전`, `교환소`로 묶는다.
- 미구현 테이블은 클릭 가능한 가짜 버튼으로 만들지 않는다. `준비 중` 정보는 진입 동작 없이 표시한다.
- 사이드바의 장식 버튼은 이번 범위에서 제거하거나 실제 동작이 있는 `로비`·`카지노`만 남긴다.

### 이어하기

이어하기는 Venue 플로어를 건너뛰고 저장된 캐비닛으로 한 번에 간다.

```text
[이어하기] 테메로세 카지노 · 도둑잡기
             12턴 · 18장 남음
```

- 최근 기록의 캐비닛이 현재 공개 Venue에 속할 때만 프로덕션 홈에 보인다.
- 숨긴 캐비닛의 저장은 삭제하지 않는다.
- 직접 URL과 복구도 같은 공개 허용 집합을 검사해 숨긴 캐비닛이 우회 노출되지 않게 한다.

## 5. 히어로와 로딩

- 첫 화면은 Venue 히어로 1장만 eager 로드한다. 초기 추가 이미지 총량은 200KB 이하로 유지한다.
- 원본 카드 에셋을 직접 참조하지 않고 `content-cli`가 만든 sm/md WebP 파생본만 사용한다.
- 이미지 실패 시 텍스트와 입장 버튼이 유지되며 CLS가 없어야 한다.
- 카지노 플로어의 테이블 아트는 플로어 진입 뒤 lazy 로드한다.

## 6. 금지사항

1. 럭키★오락실 브랜드·배경·사이드바 전체를 테메로세 테마로 바꾸지 않는다.
2. Venue 공개만으로 미구현 캐비닛이나 비공개 캐비닛을 자동 노출하지 않는다.
3. 개인 카드 업로더를 삭제하거나 데이터베이스의 기존 카드를 삭제하지 않는다.
4. 카지노 배역을 원본 정본으로 표기하지 않는다.
5. 히어로 때문에 초기 JS 200KiB gzip 예산을 늘리지 않는다.
6. 이어하기에 Venue 한 단계를 강제하지 않는다.

## 7. 검증 관문

1. 프로덕션 홈에는 테메로세 카지노 Venue 하나와 공개 RecentPlay만 보인다.
2. 소녀전선·개인 카드 UI와 그 RecentPlay가 보이지 않지만 저장 데이터는 남는다.
3. Venue 입장 뒤 공개 테이블만 보이고 도둑잡기를 시작할 수 있다.
4. 이어하기 한 번으로 정확한 캐비닛 상태에 복귀한다.
5. 직접 URL로 비공개 캐비닛을 열 수 없다.
6. 개발 빌드의 명시적 비공개 경로에서는 보존 코드를 점검할 수 있다.
7. 히어로 404에서도 제목·입장 버튼이 동작한다.
8. 모바일·데스크톱에서 로비가 중립 브랜드로 남고 카지노 내부만 테메로세화된다.
9. 초기 JS gzip 200KiB 및 홈 이미지 200KB 예산을 지킨다.

## 8. 비범위

- 두 번째 Venue의 실제 콘텐츠.
- GFL 에셋 삭제.
- 슬롯·포커·더비의 게임 규칙.
- 개인 카드 파이프라인 재공개.
